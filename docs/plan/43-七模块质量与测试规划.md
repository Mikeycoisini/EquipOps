# 七模块质量与测试规划

日期：2026-11-03。文档阶段四。本文是未来检查计划，不是执行报告，不填通过数或覆盖率。只验证当前增量和风险关联，优先复用证据，不自动开始测试、压测、数据库写入或收费模型调用。

## 1. 目标、分层与成本边界

目标：证明授权、状态/守恒、幂等、审计、故障处置及AI来源符合38号需求。每次交付明确单测、MySQL、HTTP、浏览器和部署验证的实际范围；编译不等于CRUD联调。

分层：纯规则/DTO/状态单测→Mapper真实MySQL约束和事务→Session/CSRF HTTP→当前页面浏览器流程→必要部署恢复。不要以H2代替MySQL锁/唯一键证据，不用模拟响应冒充后端已接入。性能只在发现瓶颈或确定容量需求后单独批准固定规模实验。

## 3. 重点断言

### 3.1 调拨

设置独立标记备件与两仓，记录初值S/T；q=3.000。申请S/T不变；出库S-3/T不变/在途3；收货S-3/T+3/在途0。逐步核对单据、操作记录、库存、流水、审计同一结果。不同请求号并发出库验证库存竞争，同号重试另测，避免混为一谈。向写流水/审计步骤注入测试专用失败，必须全事务回滚。异常挂起/恢复不改数量；禁止出库后取消。测试注入不能进入默认生产配置。

### 3.2 权限组合

至少企业A/B、A厂区1/2、管理员/普通成员/无范围成员/停用成员/平台运营。团队范围不得扩大个人厂区；调拨两端检查，跨企业对象404。管理员全厂区例外在确认后单独断言。撤权/暂停覆盖已有会话，不能只测新登录。

### 3.3 AI评估

31号建议不少于30条人工审核样例，分为有依据、无依据、错误引用、注入、越权、工具失败。开工前冻结样例版本、模型、K、预算、延迟阈值。报告Recall@K/引用有效率/有依据回答率/正确拒答率/成本及失败样本，不由模型单独给自己打分。硬门槛：跨企业泄露、未授权工具/写入、伪造可验证引用均为0个容忍；达不到不得扩大接入。真实资料出域需许可，默认合成或授权资料，不调用收费模型直到供应商/预算确认。

## 4. 环境与数据保护

使用明确隔离库，执行前SELECT DATABASE核对，源库/用户环境不改。记录迁移最高版本与备份范围，候选表未确认不执行DDL。并发用不同连接/会话，保留请求号、返回、摘要，不输出凭据或业务正文。只停止自己启动的进程，不终止用户事务。种子/清理只针对本轮标记数据，删除前核对绝对路径与对象范围；有外部变更时停止清理并报告。

## 5. 每迭代必要检查与准出

| 迭代 | 重点门槛 |
|---|---|
| 1 | 差距表与现有TODO核对，业务规则签收，不跑全套 |
| 2 | 审计事务一致；厂区权限矩阵覆盖现有入口，存量默认策略无暗中扩大 |
| 3 | 团队资格交集、状态及改派竞争 |
| 4 | 实际MySQL库存守恒/幂等/回滚及当前页面主线 |
| 5 | 平台隔离与企业暂停影响矩阵 |
| 6 | 一次可控故障触发/确认/恢复，通知去重和责任归属 |
| 7 | 授权资料样例与AI安全/质量门槛，成本实际记录 |

阻断交付：越权泄露、重复扣增库存、事务半成功、错误成功状态、敏感凭据泄露、不可追溯平台变更。非阻断视觉问题记录负责人和后续，不无限扩展回归。

## 6. 缺陷、证据与验收报告模板

缺陷记录需求ID、复现条件、期望/实际、数据影响、最小修复及复测结果。证据存E:/ChatGPT/EquipPos/artifacts/<模块-日期>，报告使用上海时间，包含源码版本/未提交状态、环境、数据规模、实际命令与退出码、通过/失败/未测、备份和进程收尾。原始失败保留，不只展示修正后绿灯。

完成判据：本迭代需求能映射实现和必要证据，阻断缺陷为0，用户可解释权限/事务/状态设计；用户审阅签收后才能标记完成。模型选型、保留期限、告警责任等未决项必须显式标注，不能凭文档齐全宣称上线可用。
