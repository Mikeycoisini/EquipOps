# Ch01 设计：资料问答最小闭环（不接模型）

> 状态：定稿（2026-11-10 用户确认：问题原文与答案正文落库；ch03 起的前置为 M5）
> 前置：无（不依赖 M5/M6，不依赖模型供应商）
> 依据：38 号 M7-R1；41 号第 3 节 ai_* 表；42 号第 2、3 节 AI 接口；40 号第 2 节信任边界；43 号第 3.3 节评测口径

## 1. 背景与目标

现状：M7 完全没有落地——无 `ai_*` 表、无 `com.ai` 包、无 Python 服务。

本章目标只有一件事：**把"上传资料 → 切分 → 检索 → 带引用回答 → 任务可查"这条链路在 Java + Python 两个进程之间真正跑通**，且租户隔离、任务状态机、取消、超时、引用可核对全部到位。

一句话架构：Java 持有资料原文与任务真相，Python 只做切分与检索，本章用**词面检索**代替向量检索、用**固定句式**代替模型生成。

刻意不接模型：三进程通信、任务凭证、状态机、租约、引用落库、前端交互这些架构风险必须在没有模型噪声时先跑通。否则后面任何失败都分不清是架构问题还是模型问题。

## 2. 范围

**做：**

1. Flyway `V16` 新增 5 张 `ai_*` 表，字段与唯一键按 41 号第 3 节。
2. 资料上传（仅 MD/TXT）、版本追加、逻辑删除、列表与详情接口；文件落受控目录，`storage_key` 不出接口。
3. Python 服务骨架：FastAPI、配置、健康检查、按版本建/删索引、词面检索、引用返回。
4. Java 任务：创建（幂等）、查询、取消；状态机 + 租约 + 超时 + 晚到结果丢弃。
5. 引用校验：Python 只返回 `chunkId`，**引用原文由 Java 按 chunkId 从库里重取**，不采用 Python 回传的 quote 文本。
6. 任务凭证雏形：Java 签发短期票据，Python 调 Java 内部接口时携带；Java 每次重新查库复核企业与成员。
7. 端到端冒烟脚本与第一版证据目录；评测集骨架（题面先建，阈值在 ch02 冻结）。

**不做（用户明确 / 依据）：**

1. 不接任何模型、不接向量库（ch02）。
2. 不解析 PDF/OCR（31 号：PDF 后置）。
3. 不接业务只读工具（ch03 起）。
4. 不生成维修建议、不做草稿、不写任何业务表（38 号：首版不自动写库）。
5. 不做 SSE 流式、不做多轮对话（42 号未要求；本轮只要任务态）。
6. 不做前端页面（在独立前端仓库，另立任务）。
7. 不引入 LangGraph/MCP（31 号：真实需求出现才引入）。

## 3. 架构总览与数据流

```
浏览器 ──Session+CSRF──> Java /api/ai/**
                          │
                          ├─ ai_documents / versions / chunks（原文权威源，MySQL）
                          ├─ 资料文件（受控目录 ai.doc.root）
                          ├─ ai_tasks / ai_citations（任务与引用真相）
                          └─ AiServiceClient ──HTTP 127.0.0.1:8090──> Python
                                                    Python 侧：
                                                    index（按 versionId 可删重建）
                                                    lexical 检索
                             <──X-AI-Credential── 返回 {answer, citations[chunkId]}
```

信任边界（40 号）：

- Python 不连 MySQL，只拿到 Java 推送的 chunk 文本。
- Python 回传的答案只是"建议文本"，事实与引用由 Java 复核。
- `tenantId`/`userId` 只来自 `CurrentAccessService`，请求体一律不接受。
- Python 服务只绑 `127.0.0.1`，`/internal/**` 不进浏览器可达路径。

失败行为：Python 不可用 → 任务 `FAILED` + `AI_UNAVAILABLE`，业务其余接口不受影响（`ai.enabled=false` 时 `/api/ai/**` 直接 503）。

## 5. 数据模型（V16）

| 表 | 关键字段 | 唯一/索引 |
|---|---|---|
| `ai_documents` | tenant_id、document_code、title、state(DRAFT/ACTIVE/DELETED)、created_by、created_at/updated_at | 唯一 `tenant_id+document_code`；索引 `tenant_id+state+id` |
| `ai_document_versions` | tenant_id、document_id、version_no、content_hash、storage_key、index_state(PENDING/INDEXED/FAILED)、byte_size、created_at | 唯一 `tenant_id+document_id+version_no` |
| `ai_chunks` | tenant_id、version_id、chunk_no、section、content_hash、index_ref、created_at | 唯一 `tenant_id+version_id+chunk_no` |
| `ai_tasks` | tenant_id、created_by、request_id、state、question_text、answer_text、model_ref、input_tokens、output_tokens、cost、error_code、expires_at、version、created_at/updated_at | 唯一 `tenant_id+request_id`；索引 `tenant_id+created_by+created_at+id` |
| `ai_citations` | tenant_id、task_id、chunk_id、citation_no、quote_hash、created_at | 唯一 `tenant_id+task_id+citation_no` |

说明（2026-11-10 已定）：

- `ai_tasks.question_text`、`answer_text`、`warnings_json` 是 41 号候选字典未列出的字段，**经用户确认落库**：问题原文与答案正文都保存，供任务详情回看与排障。41 号"AI 正文/问题是否存库"一项就此关闭。
- 由此产生的配套要求：答案正文随任务一起受企业隔离；资料删除后不再返回引用原文（见第 7 节第 9 条）；保留期限与清理方式仍待定，本章不引入自动清理。
- 时间统一 `DATETIME(6)`；ID 为 BIGINT，接口按字符串返回。
- 所有表带 `tenant_id`，任何查询必须拼 `tenant_id` 条件。

## 6. 接口契约

### 6.1 浏览器接口（Session + CSRF + 企业授权）

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| POST | `/api/ai/documents` | 企业管理员 | multipart：file、documentCode、title；返回 Result<AiDocumentVO> |
| GET | `/api/ai/documents` | 有效成员 | 分页 current/size/keyword，IPage |
| GET | `/api/ai/documents/{id}` | 有效成员 | 详情 + 最新版本 + index_state |
| POST | `/api/ai/documents/{id}/versions` | 企业管理员 | multipart：file；新增版本并触发重建索引 |
| DELETE | `/api/ai/documents/{id}` | 企业管理员 | 逻辑删除 + 删索引 + 撤销可检索性 |
| POST | `/api/ai/questions` | 有效成员 | `{requestId, question, documentIds[]}` → 202 `{taskId, state}` |
| GET | `/api/ai/tasks/{id}` | 创建人 | `{state, answer, citations[], warnings[], errorCode}` |
| POST | `/api/ai/tasks/{id}/cancel` | 创建人 | 200；终态返回 409 |

错误码（统一放 `errorCode`，HTTP 状态与 42 号一致）：

| errorCode | HTTP | 含义 |
|---|---|---|
| `AI_DISABLED` | 503 | `ai.enabled=false` |
| `AI_UNAVAILABLE` | 503 | Python 不可达 |
| `AI_TIMEOUT` | 504 | 超过读超时或任务总时长 |
| `AI_INVALID_REQUEST` | 400 | 问题为空/超长、documentIds 非法 |
| `AI_NO_ELIGIBLE_DOCUMENT` | 400 | 指定资料无可用版本 |
| `AI_TASK_NOT_FOUND` | 404 | 不存在或不属于本人 |
| `AI_TASK_STATE_CONFLICT` | 409 | 终态不可取消 |

### 6.2 内部接口（Python 调 Java，不开放浏览器）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/internal/ai/documents/{versionId}/index` | Java→Python 推送 chunk 列表（带 tenantId） |
| DELETE | `/internal/ai/documents/{versionId}/index` | 删索引 |
| POST | `/internal/ai/tasks` | 下发任务 `{taskId, tenantId, userId, question, documentIds[]}` |
| GET | `/internal/ai/health` | 探活 |

Java 侧接收 Python 的调用（如后续 ch03 工具网关）走 `/internal/ai/**`，独立过滤器链，只认 `X-AI-Credential`。

`X-AI-Credential`（ch01 雏形，ch03 升级为完整 JWT）：`aud=equipops-ai`、`tenantId`、`userId`、`taskId`、`scope`、`jti`、`exp`（≤10 分钟），HS256；Java 每次核对签名、过期、scope，并**重新查库**确认企业 enabled 与成员有效。

### 6.3 Python 返回

```json
{"state":"SUCCEEDED","answer":"...","citations":[{"chunkId":"123","score":0.42}],"warnings":[]}
```

- 只返回 `chunkId`，不返回引用原文（原文由 Java 重取）。
- 无命中返回 `{"state":"INSUFFICIENT_EVIDENCE","answer":"","citations":[]}`。

## 7. 关键规则

1. **租户隔离**：所有 SQL 带 `tenant_id`；跨企业 `id` 一律 404，不区分"不存在"与"无权限"。
2. **文件安全**：扩展名白名单（`.md`/`.txt`）、大小上限、编码校验（UTF-8，失败明确报错）、后端生成文件名、禁止 `..` 与绝对路径、符号链接不跟随。
3. **幂等**：`tenant_id+request_id` 唯一；同号同内容返回原任务，同号异内容 409。
4. **状态机**：`QUEUED → RUNNING → SUCCEEDED | INSUFFICIENT_EVIDENCE | FAILED | CANCELLED | EXPIRED`；全部用条件更新（`WHERE state=? AND version=?`）。
5. **取消与晚到**：取消置 `CANCELLED` 后，Python 晚到结果一律丢弃，不写 `answer_text`、不写 `ai_citations`。
6. **引用可核对**：Java 按 `chunkId` 重取 chunk，校验属于本企业、本任务所选版本；取不到的引用直接丢弃；有效引用为 0 → 降级 `INSUFFICIENT_EVIDENCE`。
7. **资源上限**：单任务总时长 30s、问题 ≤1000 字、单次检索返回 ≤20 片段、Python 调用连接 2s/读 15s。
8. **日志**：记 taskId/tenantId/耗时/状态迁移；不记资料正文全文、不记凭据。
9. **保留与删除**：问题原文与答案正文落库（已确认）；资料逻辑删除后删索引、引用不可再取原文，历史任务仍可查状态，页面标注"资料已删除，结论可能已失效"；任务保留期限与清理方式待定，本章不做自动清理。
