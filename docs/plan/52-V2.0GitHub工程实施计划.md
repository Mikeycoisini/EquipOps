# V2.0 GitHub工程实施计划

日期为2026-11-09，范围依据[总体实施方案](51-V2.0完整系统总体实施方案.md)。前后端分别使用各自GitHub仓库，通过配套接口和阶段版本交付。

## 当前已确认事实

- 后端默认连接equipops_v2，业务端口8082；前端开发端口5174并代理到后端。
- 新库已有15个成功迁移，审计为V15，告警为V13、续扫为V14。
- 后端完整启动与匿名CSRF接口在临时独立Redis环境验证通过。
- 用户、企业和必要基础角色初始化，以及完整业务验收仍待执行。

## 工程任务

1. 核对当前源码和未跟踪文件，检查配置及公开内容，保留来源和清理记录。
2. 将V2.0发布快照提交到两个独立GitHub仓库，核对分支、远程SHA及跟踪状态。
3. 建立Issue与PR模板，记录需求ID、范围、迁移、实际验证和回退说明。
4. 配置Java17与Node22构建，使用真实MySQL/Redis隔离服务验证迁移和Session入口。
5. 初始化新库角色、管理员及首个企业，补充登录、切换企业和必要权限拒绝的真实接口与页面验证。
6. 独立审查工程底座，记录同一版本的运行和证据，然后细化A2审计差距与实现任务。

## 固定验收约定

- 每次变更先说明输入、允许角色、状态流转、事务及失败行为。
- 新规则和回归风险通过针对性检查固定，实际故障按证据定位。
- 业务执行方法内部保留完整编号流程和逐行中文说明，代码与当前需求对应。
- 构建、MySQL、HTTP、浏览器及部署结果分别记录，当前提交的实际结果作为完成依据。
- 数据库和Redis目标、会话及文件根在运行前核对，所有凭据通过本机环境或受保护Secrets注入。

## 发布文件范围

保留源码、测试、锁文件、构建入口、非秘密配置示例及技术文档。运行目录、IDE文件、依赖缓存、构建产物、旧数据夹具和本机原始实验资料按.gitignore管理。

GitHub公开内容的实际提交清单与远程SHA记录在本次发布报告；后续功能按阶段Issue持续推进。
