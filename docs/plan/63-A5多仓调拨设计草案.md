# A5 多仓调拨设计草案

依据 51 号总体实施方案及 38～43 号模块设计，本阶段交付 M4-R1、M4-R2，并复用 A2 企业审计和 A3 厂区授权。当前后端 main 已包含 A4，Flyway 最新版本为 V17。

## 实施方式

采用现有 Spring Boot 单体和 MySQL 库存事务。调拨单记录业务状态及在途量，沿用仓库余额与库存流水作为库存事实来源。出库和收货分别提交事务，运输期间由调拨单承接责任。仓库目录与调拨页面使用同一套仓库和厂区授权。

## 已确认权限

2026-11-11 确认首版口径。申请、出库、完整收货、取消、登记异常和恢复均要求当前企业管理员身份，且逐次复核两端仓库所属厂区。普通有效成员仅在两端均获授权时查询调拨单。

首版异常处理限定为挂起和核验后恢复。在途数量保持不变。损耗、退运、部分收货和库存补偿另行定义结算规则。

## 仓库与调拨

- 保留 `GET /api/warehouses` 的默认仓库行为。新增仓库目录、详情和维护，复用现有创建入口。停用或改变归属前检查库存及在途责任，保留历史记录。
- 新增 `GET/POST /api/transfers`、详情，以及 `dispatch`、`receive`、`cancel`、`exceptions`、`resume` 动作。一次申请仅包含一个备件和一个正数量，源仓与目标仓必须不同且属于同一企业。
- 申请进入 REQUESTED，不预占库存。出库扣减源仓并进入 IN_TRANSIT。完整收货增加目标仓余额并进入 RECEIVED。仅 REQUESTED 可取消。IN_TRANSIT 可挂起为 EXCEPTION，核验后恢复至 IN_TRANSIT。
- 从 V18 开始新增调拨单、动作与异常记录，关联库存流水及审计。以租户与请求号判定幂等，同号同载荷重放原结果，同号异载荷返回 409。非重放的状态变更校验 expectedVersion。
- 出库和收货各自在同一事务更新余额、流水、在途状态、幂等记录及审计。仓库停用与调拨动作采用共同的仓库锁定规则，防止检查后仓库并发失效。

## 实施与验收顺序

1. 先锁企业并复核有效管理员，再锁调拨单，最后按 ID 锁仓库并校验厂区。库存动作与仓库维护使用同一企业锁，已有库存事务依靠余额行上的原子更新串行。
2. 实现 Flyway 增量迁移、仓库目录及维护、调拨查询与命令。
3. 对照真实 API 接入仓库页、调拨列表和详情。
4. 在隔离 MySQL 验证跨企业隔离、两端厂区权限、库存不足、同号重放、异载荷冲突、并发收货、事务失败回滚和库存守恒。
5. 分别记录构建、规则测试、MySQL、HTTP 和浏览器验收结果。

后端工作目录可用。当前会话访问前端仓库目录时被拒绝，前端接入需要可访问的前端工作目录。
