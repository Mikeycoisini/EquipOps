# 库存流水Excel异步导出首版设计

日期：2026-11-02。状态：设计提案，待用户确认；不是已实现功能或建表授权。

## 1. 已确认目标与协作边界

用户已选择库存流水异步导出，文件直接生成Excel `.xlsx`。当前企业所有有效成员均可导出；普通成员只读业务数据，管理员沿用既有写权限；普通成员仅查看自己的导出任务。创建导出只生成文件，不修改库存流水或余额。


不做Excel导入、历史流水编辑、消息队列、微服务、对象存储或通用报表平台，不改变现有库存写入权限。

## 2. 方案比较与推荐

以下技术选择为助手建议，随本提案一起确认，不能当作用户已逐项选定。

| 方案 | 取舍 |
| --- | --- |
| 请求内同步生成 | 实现较短，但占用请求线程，无法覆盖本阶段线程池/任务生命周期目标，不采用 |
| 内存任务表与本地文件 | 单实例容易实现，重启丢任务、另一实例无法查询状态，不推荐 |
| 数据库任务表、有界线程池、共享文件目录 | 推荐。任务状态可跨实例查询、可记录失败；同机双实例可共享目录，跨主机部署需先配置共同可读写存储 |

文件生成建议Apache POI SXSSF，数据库分批查询、按行写入。依赖版本在进入依赖配置步骤时核对Java17及Boot现有依赖后固定，不在本次安装。依据：https://poi.apache.org/components/spreadsheet/how-to.html 。临时文件和工作簿须按选定版本正确关闭/清理。

## 3. 业务与权限

1. 创建、列表、详情、下载只允许当前企业有效成员。tenantId/userId来自可信服务端身份，不接收客户端身份字段。
2. 首版所有人（包括管理员）仅能列出、查看、下载自己创建的任务，查询同时限定tenantId、createdBy和taskId。其他企业或其他人的任务返回404。
3. 管理员的写权限不自动扩大成查看他人导出。首版建议管理员可取消自己的排队/运行中任务；普通成员不能取消或编辑任务。此项是提案，不是已实现接口；如需管理员管理全企业任务，后续单独约定。
4. 已提交的筛选条件不可编辑；更换条件需新建任务。没有“修改Excel文件内容”的后端接口。
5. 后台仅接收任务ID，通过任务记录取得可信userId/tenantId。执行前、每批次和发布文件前，按这两个ID重新读取账号、企业、成员状态，不依赖HttpServletRequest、SecurityContextHolder或旧角色快照。
6. 请求线程继续使用CurrentAccessService；后台校验另设接受显式身份的最小内部能力，不伪造请求/Session，不大改CurrentAccessService已有签名。
7. 成员或账号停用后，后续批次停止、任务失败、临时文件清理；下载端也实时校验。已下载到本机的文件无法撤回；已开始传输的下载不承诺即时撤回。
8. 切换企业不改变已创建任务的企业。切到B后无法在B查看A任务；切回A且仍有权限才能查看。

## 4. 内容、格式和数据一致性

筛选沿用InventoryTransactionPageQueryDto的warehouseId、sparePartId、workOrderId、transactionType、referenceType、startTime、endTime；导出DTO不含current/size。关联对象归属和起止时间验证沿用已有业务含义，不调用每页最多100条的页面接口来拼文件。

首版建议一个工作表“库存流水”，固定表头、冻结首行、合理固定列宽，无复杂样式或公式。列为：流水编号、流水类型、仓库编号、仓库名称、备件编号、备件名称、变动数量、来源类型、来源说明、工单编号、原领料流水ID、操作人ID、备注、创建时间。未关联字段留空，不编造历史名称或用户名。

退料保留现有底层枚举，额外根据issueTransactionId展示“退料”，不新增RETURN数据库枚举。仓库/备件名称取生成时查询到的当前资料，与已有联表VO一致，不承诺历史名称快照。所有文本写入字符串单元格，不把用户文本当Excel公式；ID/编号按文本写入，quantity按数据库DECIMAL(14,3)生成数值单元格并显示三位小数，时间按上海业务时间显示yyyy-MM-dd HH:mm:ss。

建议上限：每任务100000条数据、每批1000条；无匹配数据也生成只有表头的成功文件。超过上限明确失败并提示缩小筛选，不悄悄截断。数量统计和最终写出均检查上限。

执行开始时记录本企业已可见流水最大ID作为upperBoundId，按id递增执行 `lastId < id <= upperBoundId AND tenant_id = ?` 并应用全部筛选；沿用XML联表的企业限定。导出顺序固定为流水ID升序，区别于页面时间倒序，并在页面说明。它用于排除通常后续新增流水，不是严格数据库时间点快照：已分配较小ID的未提交事务可能随后提交；关联名称也可能改变。首版不持有跨整个导出的长事务，不承诺审计快照一致性。

## 5. 任务、线程池、失败和双实例

建议状态：QUEUED、RUNNING、CANCEL_REQUESTED、SUCCEEDED、FAILED、CANCELLED、REJECTED、EXPIRED。

- 创建事务只校验条件、限制并发并保存QUEUED，事务提交后才提交执行器；不能在库存事务中写Excel。
- 首版参数为每实例2个工作线程、等待队列10，采用明确拒绝策略，不使用CallerRunsPolicy把导出退回请求线程。拒绝时保存REJECTED，返回429及taskId；不是静默丢任务或伪造成功。
- 每用户在同一企业最多1个活动任务（QUEUED/RUNNING/CANCEL_REQUESTED）；在短事务中锁定该成员关系后检查/创建，跨实例统一限制，冲突409。线程池容量是每实例限制，不宣称全局只有2个任务。
- 任务记录ownerInstanceId与唯一runToken。只有创建实例的执行器执行该任务；用条件更新保证QUEUED到RUNNING仅成功一次。另一实例只负责授权后的查询、取消请求和下载，不再次执行同一任务。
- 队列与运行任务由所属实例每5秒续期，leaseUntil建议30秒；所有执行状态更新和发布须校验runToken/当前状态及有效租约。失去租约的旧线程不得发布结果。
- 租约比较和续期使用数据库时间；续期必须同时匹配ownerInstanceId、runToken、活动状态及尚未到期的旧租约。过期后即使回收器尚未运行，也不能续租复活或重新进入RUNNING。
- 每实例每10秒扫描已到期的活动任务，用条件更新标记FAILED（WORKER_LOST），取消中的任务标记CANCELLED。首版不自动重试，用户可新建；排队任务也不能永久卡住。正常停止停止接收新任务并尽力终止；突然退出依赖租约回收。
- 单任务执行时间上限建议5分钟，后台每批/写入检查截止时间及中断；另设超时标记与协作式中断。磁盘/驱动阻塞可能无法立即终止，必须在恢复执行后再次检查状态及租约，不能把线程中断当作强制资源释放保证。
- 取消：QUEUED可条件更新到CANCELLED；RUNNING更新到CANCEL_REQUESTED，worker检查后清理文件并到CANCELLED。完成发布与取消竞争由条件更新决定，晚到取消在终态返回409。
- 取消排队任务后尽力从执行器队列移除；仍留在队列的Runnable启动时先检查状态，已取消则退出。拒绝落库也必须条件更新，不能覆盖取消或其他终态。
- 导出查询另配语句及驱动读取超时，不能只依赖5分钟批次间检查；超时终止状态/停止续租，阻塞线程恢复时重新检查租约和状态，不继续发布。具体驱动参数与效果在进入查询实现时验证。
- 权限失败、行数超限、超时、IO/查询异常分别记录可公开的错误码/提示，不给前端绝对文件路径、SQL或堆栈。每批查询结束释放数据库资源，不跨文件生成持有数据库事务。


## 6. 文件发布、下载与清理

文件根目录由配置提供，两个同机实例使用相同绝对目录；跨主机必须配置相同共享存储后才启用此能力，否则启动检查失败。不能把Session共享等同于文件共享。

SXSSF底层临时文件也必须置于受控目录，按任务/runToken区分。工作簿关闭与临时文件清理覆盖成功、失败、取消，重启后清理无有效租约的残留。建议初始磁盘参数为单任务临时文件与结果文件合计上限512MiB、文件根目录所在卷至少保留2GiB可用空间；执行环境配置步骤验证并可调整。提交/执行/写入期间检查阈值，超限明确失败并清理；不把应用检查当作操作系统硬磁盘配额，不保证两次检查间绝无短时超限。

文件名由任务ID/runToken生成，服务器保存受控相对storageKey，不接受客户端路径。写入唯一`.part`文件，完成并关闭工作簿后在同一文件系统内重命名，再以状态/租约条件更新发布storageKey和SUCCEEDED；未成功发布的文件不可下载，竞态产生的孤儿文件由清理任务回收。删除任务文件前必须校验最终路径在配置根目录内。

下载只接收taskId，经企业、本人和实时成员权限校验后解析storageKey；成功状态且未过期才流式返回xlsx，不把文件完整读进byte数组。正在处理409，过期410，跨企业/非本人404，缺少文件409并记录FILE_MISSING，不能返回空文件伪装成功。

建议文件保留24小时；到期SUCCEEDED转EXPIRED，数据库任务元数据首版保留便于审计。清理器定期删除过期文件、失败/取消临时文件及无活动租约的孤儿文件，不删除仍在使用的有效runToken文件。下载先获得文件读句柄再传输；过期清理遇到在用文件延后重试，已开始下载允许完成。磁盘空间不足时任务失败，不持续重试或无限排队。

## 7. 候选接口与第一步数据类

以下均为新候选接口，当前Controller中不存在：

| 方法 | 路径 | 含义 |
| --- | --- | --- |
| POST | /api/inventory/exports | 提交筛选，202返回taskId/状态 |
| GET | /api/inventory/exports | 分页查询本人在当前企业的任务 |
| GET | /api/inventory/exports/{id} | 查询状态、已处理条数、提示、到期时间 |
| GET | /api/inventory/exports/{id}/file | 授权下载xlsx |
| POST | /api/inventory/exports/{id}/cancel | 管理员取消本人任务，按第3节提案 |

JSON响应继续沿用Result；写请求保留CSRF。前端在InventoryView出入库流水页增加“导出Excel”和“我的导出”，沿用当前筛选，活动任务轮询建议2秒；切企业/卸载时停止轮询且丢弃旧响应，任务在后台继续按原企业执行。无文件可下载时不显示假链接。

首步仅建议创建：

- InventoryExportTaskEntity：任务归属、创建人、筛选快照字段、upperBoundId、状态、已处理条数、storageKey、文件名/大小、错误码/提示、实例/runToken/租约、创建/开始/完成/截止/过期时间；遵循邻近Entity的Lombok、MyBatis-Plus和JPA注解习惯。实体仅准备映射，不启动应用或替用户建表。
- InventoryExportCreateDto：上述7类筛选，必要格式/正数校验，不含身份、状态或文件路径。
- InventoryExportPageQueryDto：本人任务分页及可选状态。
- InventoryExportTaskVO：公开状态、条数、文件展示信息、时间和错误提示，不返回storageKey、ownerInstanceId、runToken或内部堆栈。
- InventoryExportStatus：状态枚举。失败码先用固定字符串约定，是否独立枚举在具体数据类步骤说明。

表名建议inventory_export_tasks；关联业务查询保留InventoryTransactionMapper/XML结构。建表SQL/Flyway要等用户进入数据库步骤才编写，Entity存在不代表数据库结构已创建。


验收至少覆盖：Excel实际可打开与字段类型/中文/数量/退料；筛选/空结果/超限；不是仅导出当前页；跨企业/他人任务拒绝；普通成员不能取消；成员停用阻断后台发布和下载；线程池饱和有明确状态；取消/超时/IO异常的清理；实例退出与租约回收；A创建B查状态下载；终态竞态无错误成功；后台不依赖Session；前端企业切换和晚到响应隔离。

不提前填充测试通过数，不因编译或下载接口200就认定Excel内容正确。本提案未安装依赖、创建产品数据类、建表、启动应用或执行数据库写入。
