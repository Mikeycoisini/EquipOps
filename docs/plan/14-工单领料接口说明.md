# 工单领料接口说明

更新时间：2026-10-28。本文对应当前源码，不代表真实数据库和前端已经联调完成。

## 请求

`POST /api/inventory/issues`

沿用项目的登录会话、当前企业和 CSRF 要求。请求头 `Idempotency-Key` 必填，使用1～64位 ASCII 字母、数字、下划线或短横线，区分大小写。

```json
{
  "workOrderId": 30,
  "warehouseId": 10,
  "sparePartId": 20,
  "quantity": 2.5,
  "note": "维修领用轴承"
}
```

三个 ID 必须为正数；数量必须大于0，最多11位整数和3位小数；备注可省略或为 null，最多500个字符。企业及操作人从可信登录上下文获取，请求体不提供这些字段。

## 业务规则与流程

1. 获取当前企业与用户，检查参数。
2. 按当前企业和请求号查已成功流水；同一操作人、OUTBOUND/WORK_ORDER 类型、相同工单/仓库/备件/数量/备注返回原流水，不再写库存或用料；内容不同返回409。数量比较忽略2.5与2.500的表示差异，null与空字符串备注仍不同。
3. 对新请求按仓库及厂区→备件→工单的顺序查询并加锁。仓库、厂区和备件必须属于当前企业且启用；工单必须属于当前企业、状态为 IN_PROGRESS，且当前用户为负责人。管理员没有额外绕过权限。
4. 插入出库流水占用请求号。类型固定为 OUTBOUND、来源固定为 WORK_ORDER，流水数量为正。并发请求号冲突时，以当前读重新查询和核对；其他唯一键冲突不能冒充领料成功。
5. 条件更新仓库余额：企业、仓库、备件匹配且余额足够才扣减。无余额行或不足均返回409，不创建虚假余额。
6. 用料行不存在时按工单及备件建立零数量行；已有行保留计划量、已领量和退回量。累计 issued_quantity，超出 DECIMAL(14,3) 上限时返回409。
7. 按当前企业重查保存的流水，返回数据库生成的主键和创建时间。

流水、扣库存、累计用料处于现有同一事务内，后续失败抛出异常，交由事务回滚。已成功请求的普通重试在资源校验前返回原结果；这不会产生新的领料，即使工单后来已完成。

## 返回与错误

成功使用现有 `Result<InventoryTransactionVO>`，字段为 code=200、message、data、timestamp；data 为该次流水，不是库存余额或工单用料汇总。

| HTTP状态 | 含义 |
| --- | --- |
| 400 | 缺少/非法请求号，请求体、ID、数量或备注不合法 |
| 403 | 当前用户不是工单负责人，或可信身份检查拒绝 |
| 404 | 当前企业内找不到目标仓库、备件或工单 |
| 409 | 资源停用、工单状态不允许、请求号冲突、库存不足、累计溢出、锁冲突或关联约束冲突 |
| 500 | 流水保存/重查失败或其他数据库异常 |

错误使用现有 Result 的 code/message/timestamp 格式，不返回 SQL 或连接信息。锁冲突可等待后使用原请求号和相同请求体重试；参数内容改变应作为新业务使用新请求号。

## 部署与验证边界

- 依赖 V5 的 warehouse_stock，以及 V6 的 request_id 和企业内唯一键；必须先核对目标数据库迁移状态。本轮没有执行迁移、回填或数据库写入。
- 当前自动化验证使用数据库边界替身、MyBatis XML解析和独立 MockMvc。它们不验证真实 MySQL SQL执行、并发锁、唯一键竞争或事务回滚，也不验证 Session/CSRF 安全链和前端页面。
- 真实联调还需验证首次领料、重复请求、并发扣减、库存不足、累计失败回滚及跨企业访问。应用启动可能触发 Flyway，不将“启动应用”当作无副作用检查。
