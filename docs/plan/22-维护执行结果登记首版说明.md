# 维护／巡检执行结果登记首版说明

日期：2026-10-30。用户已委托完成当前登记接口；本文件记录本轮开工说明和实际实现口径，不代表其他执行记录查询接口已经实现。

## 接口与请求

`POST /api/maintenance-plans/{id}/executions`

- 使用现有Session登录、当前企业选择及CSRF机制，操作人必须是计划负责人；管理员不自动拥有代执行权限。
- 必填请求头 `Idempotency-Key`：1～64位英文字母、数字、下划线或短横线。一次操作生成一个请求号，失败重试保留原号，下一次业务操作使用新号。
- 请求体 `{"result":"已完成巡检，未发现异常"}`。结果说明必填、非纯空白、最多2000字符，保存时去除首尾空白。
- 返回 `Result<MaintenanceExecutionVO>`，包括执行记录ID、计划与设备快照、本期原定日期、实际完成时间、执行人、结果及本次推进后的日期。

## 本次首版规则

1. 计划必须属于当前企业、已启用且已到期（上海日期）；暂不允许提前完成。
2. 实际完成时间由服务端按Asia/Shanghai取得；下次到期日为实际完成日期加周期天数。
3. 延期多期只登记本次实际完成记录，不补造过去漏做的记录，不自动生成维修工单。
4. 同企业请求号唯一，同企业同计划同一原定到期日唯一。同一操作人对同计划和相同归一化结果重试，返回原记录，不再次推进日期；请求号被其他内容使用时返回409。
5. 原操作成功后，即使计划停用或改负责人，原执行人仍可凭原请求号与原内容取得原记录，但当前账号及企业成员关系必须仍有效。
6. 原定日期、周期、计划名称、执行内容、设备和人员名称保存为快照，之后编辑计划不覆盖执行历史。

## 实现与验证边界

- 执行方法使用READ_COMMITTED事务及计划行锁；等待锁后重新检查有效访问。记录写入、日期更新及回查在同一事务内完成。
- 读已提交和锁后请求查询避免使用早期快照；数据库双唯一约束防止重复记录。锁冲突返回409，重试必须沿用请求号。
- 新增V9先建立计划(tenant_id,id)唯一索引，再建立maintenance_executions。V1～V8未修改。
- 本轮未执行V9、未启动应用。下次启动时Flyway会应用待执行迁移，启动前应核对目标数据库。
- 测试包含HTTP绑定、真实MyBatis参数绑定、业务边界，以及使用内存资源的Spring事务代理测试。它们不等同于真实MySQL迁移、锁等待、并发、回滚或前端联调验证。
