## 0. 如何阅读

- **S1**：可面试演示的多租户维修闭环；**当前S2**：17号补充方案的维护巡检、设备备件适配、二维码和统计；原多厂区维修团队试用为后续规划；**S3**：依据真实试用反馈做正式运行加固。
- 表内 URL、HTTP 方法为**候选契约**。实施每组接口前，必须与现有前端 `src/services/api.ts`、后端 Controller、DTO 和数据库迁移核对，确认后再固化；不得把此表当作已运行事实。
- 表中的“只读汇总”“备份恢复”“监控告警”等不一定适合暴露公开 HTTP API；文档会明确写为内部能力或运维流程。
- 业务 API 使用服务端验证的**当前租户**，不得信任请求体中的 `tenantId` 或 `actorUserId`。S2 的厂区／仓库权限叠加在租户权限之上。库存、调拨等重复执行风险高的命令需提供业务请求号（候选请求头 `Idempotency-Key`）。
- 所有分页、详情、统计、导出、审计及后台任务都必须带租户范围；无权访问其他租户对象时不能暴露对象详情。候选错误语义：400 入参错误、401 未认证、403 当前租户内无权限、404 当前可见范围内不存在、409 状态／库存／重复请求冲突、5xx 内部故障。

## 1. 原全项目功能总览（当前S2以24号清单为准）

| 模块 | S1：最小可用闭环 | S2：团队试用增量 | S3：按真实运行需求加固 |
| --- | --- | --- | --- |
| A. 账号／租户／授权 | 登录、我的企业、切换企业、成员与角色 | 厂区／团队授权、撤权与跨厂区协作 | 平台租户生命周期、权限复核、可选企业 SSO |
| B. 设备档案 | 登记、查询、修改、状态／停用、维修履历 | 多厂区设备范围和跨厂区移交规则 | 容量与归档策略；按实际需求对接资产系统 |
| C. 维修工单 | 报修、派单、开始维修、提交验收、通过／退回、时间线 | 厂区范围、改派协作、跨团队规则 | 按实际使用情况决定 SLA／升级流程 |
| D. 备件与仓库库存 | 备件目录、默认仓库、入库、领用、退回、流水与低库存查询 | 多仓库管理、租户内调拨、在途与异常处置 | 容量优化；按需要对接采购或外部仓储 |
| E. 工作台／报表 | 真实租户范围的待办与库存风险汇总 | 厂区范围统计与受控导出 | 根据真实报表需求及数据量优化 |
| F. 审计／运维 | 工单日志、库存流水、关键业务日志、健康检查 | 管理审计、备份恢复演练、监控告警与值守 | 恢复目标验证、安全审查、升级回滚与容量治理 |

S1 必须有两个测试租户，但不要求公开自助注册；租户与首批账号可通过受控初始化建立。每租户的默认厂区和仓库是**真实数据归属**，不是为了展示而造的空模块。

## 2. S1：多租户维修闭环

### A. 账号、租户和成员

**功能 A1：全局账号登录与身份查询。** 一个人可以加入多家企业，账号本身不等于租户权限。

| 候选接口 | 功能与约束 |
| --- | --- |
| `POST /api/auth/login` | 校验账号与密码；返回全局身份会话或进入选择企业步骤；不在响应中泄露密码或其他企业数据 |
| `GET /api/auth/me` | 返回当前账号及已验证的当前企业／角色摘要；没有活动企业时仅返回全局身份 |
| `POST /api/auth/logout` | 退出当前会话；具体失效方式与 Token 方案一起评审 |

**功能 A2：查看与切换企业。** 服务端核验成员关系、启停状态与角色，切换后签发仅针对目标企业的会话。

| 候选接口 | 功能与约束 |
| --- | --- |
| `GET /api/tenants/mine` | 列出账号目前可进入的企业，不提供其他企业的成员或业务数据 |
| `POST /api/auth/active-tenant` | 提交拟进入的企业 ID；核验有效成员关系后切换当前租户，不把客户端 ID 当作授权事实 |

**功能 A3：企业成员管理。** 由本企业管理员维护成员关系；一个人在不同企业可有不同角色。

| 候选接口 | 功能与约束 |
| --- | --- |
| `GET /api/tenant-members` | 查询当前企业成员、状态及角色，支持分页／筛选 |
| `POST /api/tenant-members` | 将已存在的全局账号加入当前企业；初始角色受管理员权限控制；S1 不做公开自助注册 |
| `PUT /api/tenant-members/{id}/roles` | 修改该成员在当前企业的角色；不得修改其他企业成员 |
| `PATCH /api/tenant-members/{id}/status` | 启用或撤销成员关系；撤权后后续业务请求立即被拒绝 |

### B. 设备档案

**功能 B1：设备登记与查询。** 设备属于当前企业的默认厂区；资产编号在租户内唯一，不同企业可重复。

| 候选接口 | 功能与约束 |
| --- | --- |
| `GET /api/equipment` | 按当前租户分页查询，支持名称、状态等筛选；不能在结果中混入其他租户 |
| `GET /api/equipment/{id}` | 查看当前租户下的设备详情；猜测其他租户 ID 不得返回详情 |
| `POST /api/equipment` | 登记设备；服务端设置租户／默认厂区，拒绝重复资产编号 |
| `PUT /api/equipment/{id}` | 修改可编辑档案字段；不允许通过请求体修改成其他租户归属 |

**功能 B2：设备状态与维修履历。** 停用或删除要检查未结束工单与历史引用。

| 候选接口 | 功能与约束 |
| --- | --- |
| `PUT /api/equipment/{id}/status` | 按明确状态规则变更，使用预期旧状态避免并发覆盖 |
| `DELETE /api/equipment/{id}` | 仅在没有不能删除的业务引用时允许；有历史工单时应拒绝并优先使用停用，是否改为纯软停用需在契约评审确定 |
| `GET /api/equipment/{id}/history` | 查询当前设备关联工单与维修履历，按时间分页并受租户范围限制 |

### C. 维修工单

**功能 C1：报修与查询。** 首版状态为 `PENDING`、`IN_PROGRESS`、`AWAITING_ACCEPTANCE`、`COMPLETED`；派单不改变 `PENDING`，由负责人字段区分是否已派单。

| 候选接口 | 功能与约束 |
| --- | --- |
| `GET /api/work-orders` | 当前企业工单分页、状态／优先级／设备／负责人筛选；不得跨租户返回 |
| `GET /api/work-orders/{id}` | 工单详情，包含权限允许的设备信息、用料摘要与时间线 |
| `POST /api/work-orders` | 报修；设备必须属于当前企业，创建人取自认证上下文；工单与创建日志同事务 |

**功能 C2：派单与维修。** 对每个命令校验旧状态、角色、对象归属与当前租户。

| 候选接口 | 功能与约束 |
| --- | --- |
| `PUT /api/work-orders/{id}/dispatch` | 仅派单人可选择当前企业有维修资格的成员；未派单条件更新，重复／并发派单不覆盖成功结果 |
| `POST /api/work-orders/{id}/start` | 负责人开始维修，`PENDING → IN_PROGRESS`；无负责人或非本人不得开始 |
| `POST /api/work-orders/{id}/repair-notes` | 补充维修处理记录／结果；只能在允许的状态和授权范围内追加，保留操作者与时间 |

**功能 C3：验收与履历。** 报修人或有验收权限的主管验收；维修执行人不能验收自己的工单。

| 候选接口 | 功能与约束 |
| --- | --- |
| `POST /api/work-orders/{id}/submit-acceptance` | 负责人提交维修结果，`IN_PROGRESS → AWAITING_ACCEPTANCE` |
| `POST /api/work-orders/{id}/approve` | 合格验收，`AWAITING_ACCEPTANCE → COMPLETED`；记录验收人及完成时间 |
| `POST /api/work-orders/{id}/reject` | 退回维修，`AWAITING_ACCEPTANCE → IN_PROGRESS`；必须记录退回原因 |
| `GET /api/work-orders/{id}/logs` | 按时间读取状态、派单、维修与验收日志；日志与工单一同受租户隔离 |

S1 **不实现**取消、重新打开、复杂审批链；日后新增状态必须同步更新数据库迁移、状态矩阵和测试。

### D. 备件目录与默认仓库库存

**功能 D1：备件目录和仓库库存查询。** `spare_parts` 保存备件主数据；实际数量位于仓库库存。S1 每租户只有一个默认仓库，但接口和流水显式包含仓库。

| 候选接口 | 功能与约束 |
| --- | --- |
| `GET /api/spare-parts`、`GET /api/spare-parts/{id}` | 当前企业备件目录分页与详情，支持编号／名称搜索 |
| `POST /api/spare-parts`、`PUT /api/spare-parts/{id}` | 创建／修改备件主数据；不能直接用目录修改库存余额 |
| `GET /api/warehouses` | S1 返回当前企业的默认仓库，便于后续多仓扩展 |
| `GET /api/warehouse-stocks` | 按仓库、备件、低库存条件查询余额；必须为当前企业的仓库 |

**功能 D2：入库、工单领用与退回。** 写接口均校验正数量、可信操作人和业务请求号；库存、用料与流水同事务。

| 候选接口 | 功能与约束 |
| --- | --- |
| `POST /api/inventory/stock-ins` | 向当前企业仓库入库；写入库存流水，重复业务请求不重复增加 |
| `POST /api/inventory/issues` | 从指定仓库向同租户有效工单领料；原子扣减，库存不足或重复请求不能多扣 |
| `POST /api/inventory/returns` | 关联原领用流水退回原仓库；累计退回不可超过原领用 |
| `GET /api/inventory/transactions` | 按备件、仓库、工单、类型、时间查询当前租户库存流水 |
| `GET /api/work-orders/{id}/parts` | 查看工单用料、已领及已退数量，不能代替原始库存流水 |

### E. 工作台与技术支撑

**功能 E1：真实工作台汇总。** 仅使用当前租户可见业务数据，不伪造 KPI。

| 候选接口或内部能力 | 功能与约束 |
| --- | --- |
| `GET /api/workspace/summary` | 汇总当前企业待派单、维修中、待验收、低库存数量；具体字段与前端契约核对 |
| 内部：工单日志、库存流水与请求关联 ID | 支持审计和故障排查；不向普通用户暴露全租户原始日志 |
| 内部：健康检查、配置校验、Flyway 迁移 | 新环境可复现部署；密码等敏感配置只从安全配置源读取 |

### S1 整链验收

使用两个企业、多个角色，演示“登录 → 切换企业 → 登记设备 → 报修 → 派单 → 维修领料 → 提交验收 → 他人验收 → 查看履历”。自动化反例至少覆盖跨租户猜 ID、撤权、维修人自验收、并发派单、最后一件并发领用、重复请求和流水失败回滚；以真实 MySQL 测试结果为证据。

## 3. 原S2多厂区维修团队试用（后续规划）

S2 沿用 S1 的业务接口并增加厂区／仓库范围，不重新定义当前租户或库存真相。以下为增量功能。

### A. 厂区、团队与细粒度授权

**功能 A4：厂区／团队管理。** 管理当前企业内部组织；不引入跨企业共享厂区。

| 候选接口 | 功能与约束 |
| --- | --- |
| `GET/POST /api/sites`、`GET/PUT /api/sites/{id}` | 厂区列表、登记、详情与修改；停用前检查活跃设备和工单 |
| `GET/POST /api/teams`、`GET/PUT /api/teams/{id}` | 维修团队查询与维护；团队属于当前租户，按厂区建立工作范围 |
| `GET/PUT /api/tenant-members/{id}/site-scopes` | 查询与授予成员厂区范围；撤权后列表、详情、写操作同步生效 |

**功能 A5：跨厂区协作。** 工单改派或跨团队移交必须记录原负责人、目标负责人和原因；目标成员要有目标厂区授权。

| 候选接口 | 功能与约束 |
| --- | --- |
| `POST /api/work-orders/{id}/reassign` | 租户内受权改派；并发更新不覆盖对方操作，并写时间线 |
| `GET /api/audit-events` | 管理员按操作者、厂区、对象查询关键权限和业务动作；严格按当前企业过滤 |

S1 设备、工单、库存、工作台接口均增补厂区范围校验；不能只在新接口加限制。导出、统计和定时任务同样受范围控制。

### B. 多仓库与调拨

**功能 D3：仓库管理。** 仓库属于某租户和厂区，停用不能使在途调拨或剩余库存失去归属。

| 候选接口 | 功能与约束 |
| --- | --- |
| `POST /api/warehouses`、`GET /api/warehouses/{id}`、`PUT /api/warehouses/{id}` | 创建、查询、修改仓库；首阶段已有的 `GET /api/warehouses` 扩为列表 |
| `GET /api/warehouse-stocks?warehouseId=...` | 查询指定仓库余额与低库存风险；受厂区／仓库授权限制 |

**功能 D4：租户内仓库调拨。** 候选状态为申请、源仓出库／在途、目标仓确认入库、异常待处理；取消只允许在未出库时进行，出库后的差错由受控异常流程处理，具体角色与单据字段在 S2 详细设计时定稿。

| 候选接口 | 功能与约束 |
| --- | --- |
| `POST /api/transfers` | 申请调拨，校验源／目标仓库同租户且不同仓库、数量为正 |
| `GET /api/transfers`、`GET /api/transfers/{id}` | 按状态、仓库和时间查询当前租户调拨单及流水 |
| `POST /api/transfers/{id}/dispatch` | 源仓出库并进入在途；库存不足、并发和重复执行安全 |
| `POST /api/transfers/{id}/receive` | 目标仓确认入库；重复确认不重复增加；保留源仓、在途、目标仓关联记录 |
| `POST /api/transfers/{id}/cancel` | 仅在允许状态取消；不得隐式抹掉已发生的出库流水 |
| `POST /api/transfers/{id}/exceptions` | 登记在途异常与处理结果；权限、差异处理及补偿规则须先评审 |

### C. 受控导出、恢复与值守

| 候选接口或内部能力 | 功能与约束 |
| --- | --- |
| `POST /api/exports`、`GET /api/exports/{id}` | 按当前企业与厂区权限生成、查看受控报表；下载再次校验授权，避免文件链接跨租户泄漏 |
| 内部：监控指标与告警 | 监视接口失败、后台任务失败、库存异常和恢复任务；每条告警有负责人和处置手册 |
| 运维流程：备份、隔离恢复、数据核对 | 恢复到隔离环境并核对工单、用料及流水；共享库的单租户恢复不得直接对在线库删表／重导 |
| 运维流程：故障记录与值守交接 | 记录故障影响范围、时间、原因、恢复动作和后续整改；不是新增普通业务 CRUD 模块 |

### S2 整链验收

两个企业、多个厂区和仓库：一名跨企业成员切换身份、在授权厂区处理工单并完成仓库调拨；测试其他厂区越权、撤权、源仓库存不足、重复确认和途中异常。通过一次隔离恢复及一次告警演练，保留核对与处置记录。

## 4. S3：正式运行评估与按需扩展

S3 不预先承诺增加多少业务菜单。以下分为**正式运行必备能力**与**条件触发能力**；未得到试用团队的实际需求与验收规则前，不固化完整 API。

### F. 平台租户生命周期与运行治理（必备能力）

| 功能 | 候选接口或交付物 |
| --- | --- |
| F1. 平台受控开通／暂停企业 | 平台专用的 `POST /api/platform/tenants`、`PATCH /api/platform/tenants/{id}/status` 候选接口；与普通租户业务入口隔离，保留审批和审计。不能随意物理删除仍有业务数据的企业 |
| F2. 周期性权限复核 | 管理员审阅企业成员、厂区权限、平台运营权限及撤权记录；必要时提供受控报告接口 |
| F3. 数据保留与导出 | 根据实际合同和数据责任确定期限、范围、脱敏与退出流程；异步导出／清理接口仅在规则批准后设计 |
| F4. 升级与回滚 | Flyway 迁移演练、兼容窗口、数据库备份和回退手册；不能把“代码能回滚”误认为“数据能回滚” |
| F5. 容量与灾难恢复 | 用实际负载设定并验证容量、恢复时间和可接受的数据损失目标；故障演练、告警与值守责任交接 |
| F6. 安全验收 | 跨租户及厂区隔离复测、依赖风险审查、密钥轮换、权限审计和问题整改记录 |

### 按真实需求触发的扩展，不计入默认完成范围

| 条件 | 可能新增的能力／接口方向 |
| --- | --- |
| 团队需要超时升级 | 工单 SLA 规则、超时任务与通知记录；先确定工作日历和升级责任，再设计规则 API |
| 需要可靠异步通知或外部系统集成 | Outbox 与幂等消费者；通知或集成接口需以真实失败重试要求设计 |
| 企业要求统一身份 | 企业 SSO／身份提供方对接；需先明确账号映射与跨租户授权关系 |
| 租户提出物理隔离或合规合同要求 | 评估独立 Schema／数据库迁移、备份与运维成本，而非只增加过滤条件 |
| 备件采购成为真实瓶颈 | 再设计补货申请与采购闭环；不提前扩成大量采购／财务 CRUD |

### S3 结束判断

以实际试用团队签收的运行要求、恢复与升级演练、安全整改及值守机制为准；不能仅凭功能数量或一次压测宣布“生产级”。任何性能、可用性和恢复指标都要有测试环境、数据规模和原始记录。
