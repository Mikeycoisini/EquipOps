# A2 企业侧统一审计交付与验证

日期：2026-11-09（上海）。依据51号A2、38号M1-R1/R2及58号执行计划。

## 交付范围与契约

本阶段接入已有动作枚举的三项成员敏感操作：新增成员、变更角色、启用/停用。M3改派、M4调拨和M6平台动作随相应阶段扩展，不通过全局AOP采集全部请求。审计只追加，管理员可查看本企业列表和详情，没有编辑/删除入口。

复用V15及GET `/api/audit-events`、`/api/audit-events/{id}`，不修改V1—V15、不新增迁移。分页/筛选延续当前DTO，ID=0、偏移溢出、无效参数400；无管理权限403；其他企业或不存在事件404。未选择企业、账号/成员已失效时沿用实时授权，不相信客户端tenantId。

## 授权、事务与失败

`TenantMemberServiceImpl`保留原事务边界，成功审计为MANDATORY：成员/角色写入、回查和成功审计一起提交，任一步失败整体回滚。相同状态或相同角色集合重试不增加成功审计。角色前值在企业及成员锁内使用锁定读获得，避免等待锁前的RR快照污染审计内容。添加成员同样执行角色授予白名单，不能通过新增接口授予配置外角色。

`AuditedTenantMemberService`是Primary非事务编排入口，通过明确Qualifier调用原Spring事务代理。它先建立可信当前企业身份，再等待业务代理完成提交/回滚；失败后使用REQUIRES_NEW分别追加FAILURE/DENIED。记录时不保存猜测的对象ID，只保存可信用户、当前企业、固定动作和安全错误码。审计存储再次失败时记录固定警告并重新抛原异常实例，不覆盖原始业务结果。

三种已知成员写动作在过滤器先行403时，重新核实可信当前企业身份后补记DENIED，保留原拒绝规则；身份重查或审计存储出现运行时故障仍返回原403。无法取得可信企业身份的鉴权失败，以及Controller参数绑定/校验失败，不猜测企业并强行写审计；这些仍按安全HTTP拒绝。当前首版覆盖的是三种成员敏感动作的过滤器授权拒绝及已进入业务服务的写入，不是全量请求日志。读取审计本身不批量生成审计事件。

## 脱敏与展示

按动作重建白名单；未知键、任意正文、账号姓名、密码令牌及嵌套对象不写入changes：

| 动作/结果 | 可保留内容 |
|---|---|
| MEMBER_ADDED成功 | 正目标userId、enabled布尔、受支持的roleCodes集合 |
| MEMBER_ROLES_CHANGED成功 | 固定field=roleCodes，前后角色集合 |
| MEMBER_STATUS_CHANGED成功 | 固定field=enabled，前后Boolean |
| FAILURE / DENIED | 仅errorCode |

当前支持的企业角色为TENANT_ADMIN、ACCEPTOR；集合去重排序且最多两个元素。扩展角色时必须同步白名单、规则与测试。错误码仅UNAUTHORIZED/FORBIDDEN/INVALID_ARGUMENT/NOT_FOUND/CONFLICT/INTERNAL_ERROR；未知值归一化，不存异常消息、SQL或请求正文。固定字段和有限集合使新增JSON保持有界，不靠任意字符串截断保密。

历史记录读取同样按动作和结果类型过滤；失败记录不显示成功前后值。异常JSON只记录事件ID，不输出原文或解析异常。审计id/actorUserId/objectId及changes.userId使用十进制字符串保持BIGINT精度，禁止前端转为Number；changesJson为内部字段不序列化；列表摘要仅从归一化字段生成。requestId仅接受1—36个字母数字/下划线/短横线，否则留空；审计发生时间明确使用上海业务时区。

成员与审计入口新增局部异常适配：保留明确4xx业务语义，内部数据库或程序失败统一500安全提示，不向前端泄露内部异常。

## 前端

管理员侧栏新增“操作审计”及`/audit`，支持分页、动作/操作者/对象/结果/时间筛选和只读详情。列表复用usePage，详情使用独立请求序号与store.epoch；关闭弹窗、企业切换及离开路由均作废旧响应。普通成员菜单隐藏和路由限制不代替后端授权。所有详情用Vue文本插值展示，禁止v-html及changesJson回显。

## 验证与复现

沿用57号已确认的A1隔离服务/变量，设置`A2_MYSQL_TESTS=true`后执行`bash scripts/a1_verify.sh`。该脚本在运行Spring测试前只读校验实际库、隔离Session命名空间及文件根；随后运行完整后端测试、独立日志测试、重复初始化、A1 HTTP及A2 HTTP检查。A2 HTTP脚本只连接loopback，最后恢复测试成员启用状态。GitHub工作流同样开启真实MySQL场景并上传安全结果JSON。

真实事务测试使用每次UUID标记的隔离对象，清理只删除本轮对象。审计失败以测试专用MockitoSpyBean对SUCCESS插入进行受控注入，核对真实MySQL成员变更回滚且独立FAILURE提交；没有加入生产故障开关。最初使用数据库触发器的尝试因验证用户没有SUPER权限而未执行，此失败日志保留；未修改服务器权限或关闭二进制日志校验。

前端执行`npm run test:contracts`、`npm run build`；可选浏览器脚本`scripts/a2_browser.cjs`依57号配置本机Playwright/Chromium与受保护测试密码，验证真实列表/详情、关闭在途详情后切企业、晚到响应丢弃、菜单/路由/API拒绝及退出。

## 独立审查与边界

独立审查确认事务代理接线、可信身份、前端竞态防护基本符合设计，发现失败入口仍可能保留合法成功changes。新增精确载荷与历史读取反例先红，再按结果类型分支重建写读白名单；最终全套复测另行登记。未进行第二轮独立审查。

证据保存在受Git忽略的`artifacts/a2`及A1复用脚本的`artifacts/a1`，失败尝试不删除。以下最终结果在实际运行完成后补齐；不能用源码存在或构建成功替代业务验证。生产容量、审计归档/保留期与外部监控告警尚未实施；审计库不可用时失败记录可能丢失但原业务错误仍返回，成功敏感写入则拒绝提交。
