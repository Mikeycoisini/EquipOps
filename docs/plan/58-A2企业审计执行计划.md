# A2 企业侧统一审计执行计划

日期：2026-11-09。依据51号A2、38号M1-R1/R2和57号交接。用户要求A1完成后开始A2。

## 目标与方案

复用V15的audit_events及既有查询接口，逐项补齐统一脱敏审计。成功审计必须与业务同事务；失败、拒绝审计独立事务，不伪造成功也不覆盖原始异常。可信企业、操作者来自服务端授权上下文，跨企业资源请求不写入目标企业的信息。平台身份与平台审计留A6。

采用显式服务调用和事务外失败记录，不使用全接口AOP自动采集正文。后者容易泄露密码、把业务回滚记录成成功，且难以可靠区分可信企业。优先接入已定义动作枚举的成员加入、角色及启停变更；其他敏感动作逐项定义安全字段与动作编码后扩展，不批量捕获请求参数。

## 顺序与验收

- [ ] 单元1：修复查询极端页码溢出、ID=0、列表摘要；按安全白名单读取/输出变更，异常JSON不回显原文。管理员允许、普通成员403、跨企业404保持。
- [ ] 单元2：补齐appendFailure/appendDenied与有限长度脱敏，明确安全错误码；成功写入异常触发业务回滚，独立失败记录异常不覆盖原始业务异常。
- [ ] 单元3：成员敏感写入接入成功事务及事务外拒绝/失败记录，覆盖幂等/重复动作、旧会话实时撤权、写入失败回滚；补真实MySQL验证。
- [ ] 单元4：管理员审计列表/详情前端，动作/时间/对象/结果筛选，企业切换清理与晚到响应保护；真实HTTP及浏览器验证。
- [ ] 单元5：独立审查、实际结果归档、配套提交/远程CI与阶段状态。未测项目不得宣称完成。
