# EquipOps V2.0 完整系统总体实施方案

日期为2026-11-09。当前仓库承载完整业务产品线，功能状态以源码和实际验证记录为准。

## 项目与仓库

- 后端仓库为[Mikeycoisini/EquipOps](https://github.com/Mikeycoisini/EquipOps)。
- 前端仓库为[Mikeycoisini/OPS-V2.0-](https://github.com/Mikeycoisini/OPS-V2.0-)。
- Agent承担后端、前端、迁移、测试及文档，用户决定产品范围、费用与阶段验收。
- 两仓使用配套版本与接口契约，开发和验证使用独立数据库、会话及文件目录。

## 技术架构

沿用Java17、Spring Boot4、MyBatis/MyBatis-Plus、MySQL和Redis Session，前端采用Vue3、TypeScript与Vite。Python AI服务在核心业务和授权稳定后集成，Java负责逐次业务授权。

GitHub承载Issue、分支、PR、CI和发布记录，Agent可在获授权的本地或托管工作区执行。当前核心源码仍采用Java模块化单体。

## 功能范围

| 标识 | 目标 |
|---|---|
| B0 | 认证、企业、成员角色、设备、工单、备件库存、维护、适配、统计、二维码、导出及当前告警基础 |
| M1 | 统一脱敏审计、敏感动作事务一致、失败与拒绝记录、管理员查询 |
| M5 | 厂区维护、成员显式范围、动态撤权及全入口范围贯通 |
| M3 | 团队、成员与厂区交集、受控改派和责任交接 |
| M4 | 多仓维护、单行申请、出库、在途、完整收货、出库前取消与异常挂起 |
| M6 | 平台身份、企业开通/暂停/恢复、后台与下载联动 |
| E1/E2 | 运行小时维护、到期生成工单、故障分类、维修工时与停机指标、备件适配约束 |
| M2+ | 固定规则扩展、最小外部可用性探测、站内提醒与处置 |
| M7 | 授权资料引用问答、无依据拒答、白名单只读业务工具及预算控制 |
| R1 | 组合业务验收、可复现部署、升级、备份恢复与版本发行 |

## 阶段与依赖

| 阶段 | 交付重点 | 验收门槛 |
|---|---|---|
| A0 | 基线与差距、来源、迁移映射 | 当前源码完整、来源可追溯、迁移版本唯一 |
| A1 | GitHub工程底座、隔离环境、CI | 新克隆可构建并连接隔离服务，公开资料完成检查 |
| A2 | M1企业侧审计 | 业务原子性、脱敏、成功/失败区分、企业授权通过 |
| A3 | M5厂区范围与存量回填 | 列表、详情、写入、统计、导出、下载、后台越权检查通过 |
| A4 | M3团队协作 | 状态约束、个人与团队范围交集、改派竞争及历史连续性通过 |
| A5 | M4多仓调拨 | 库存守恒、幂等、并发收货、失败回滚与两端授权通过 |
| A6 | M6平台生命周期 | 平台身份、动作审计与查询授权、暂停和恢复联动通过 |
| A7 | E1/E2维护与分析增量 | 数据采集与指标口径明确，各子项单独验收 |
| A8 | M2固定规则扩展 | 故障/恢复证据可信、去重冷却、责任及数据隔离通过 |
| A9 | M7先资料问答再只读工具 | 引用、拒答、注入及越权反例、预算实测通过 |
| A10 | 系统集成和发布 | 需求到代码/测试可追溯，阻断缺陷清零，发布证据对应同一版本 |

M1平台身份与审计授权在A6组合验收。多行调拨、部分收货、外部通知渠道和生产集群进入后续独立版本需求。

## 交付流程

需求Issue明确目标、角色、状态、数据与验收条件；当前设计确认后形成执行计划。Agent在独立分支实现，运行针对性检查并接受独立审查，PR通过实际CI及阶段验收后合并。

数据库变更使用Flyway；跨企业泄露、重复库存变更、事务半成功、虚假成功及敏感信息泄露阻断发布。CI规则能力按GitHub实际权限和账号方案核对。
