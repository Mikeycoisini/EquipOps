# A7 小时维护阈值与工单

设备档案增加小时维护阈值。企业管理员设置或调整下一次累计小时阈值，具备设备访问权限的成员可以查看。每台设备同时维护一个阈值，正数，最多 12 位整数和 2 位小数。

- GET /api/equipment/{equipmentId}/runtime-maintenance 返回当前阈值与已生成工单信息。未配置时阈值为空、版本为 0。
- PUT 同一路径提交 {"thresholdHours":100.00,"expectedVersion":0}，保存后返回当前阈值。首次配置时，如果最新实测读数已达到阈值，立即生成工单。
- 后续登记读数达到或越过阈值时生成普通优先级、待派单工单。工单描述保存阈值与触发读数，沿用现有派单与验收流程。重复提交当前阈值返回原结果，使用旧版本修改阈值返回 409，已有配置时，修改阈值须高于当前实测读数。
- 每次设置新的阈值后，历史工单可从设备关联工单查询。日期周期计划仍通过既有入口办理。

实施顺序

1. 用隔离 MySQL 扩展 A7 验收用例，先验证边界及故障回滚。
2. Flyway V21 建立设备阈值表，用企业、厂区、设备复合键限制归属，纳入厂区权限。登记读数及配置阈值共用设备行锁，同事务创建工单、日志及写入工单关联。
3. 设备档案提供阈值维护和状态展示，并在登记读数后刷新。
4. 验证权限、阈值以下、相等与越过、首次配置即时触发、并发重试、下一阈值、故障回滚及日期计划回归。

## 验证

- JDK 17 后端套件共 597 项，551 项通过，46 项按环境开关跳过。
- 隔离 MySQL 8.4.9 全新库应用 V1–V21。验证同值并发仅建一单、低于阈值不建单、达到或越过阈值触发、首次配置即时触发、越厂区和越企业隔离、过期配置冲突、工单日志写入失败回滚。
- MVC 契约验证阈值输入、响应及长工单 ID。前端构建及 99 项契约测试通过。真实登录后的浏览器联调、存量库升级和部署验收待执行。
