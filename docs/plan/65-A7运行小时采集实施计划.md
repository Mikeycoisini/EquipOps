# A7 运行小时采集实施计划

对应 51 号方案的 E1/E2 运行小时维护。设备档案现有的 runtimeHours 可手工覆盖，缺少记录时间及录入人。小时维护以新增的累计读数记录为数据来源。存量设备的首次读数由现场录入，保留 0 小时这一有效值。

| 接口 | 行为 |
| --- | --- |
| GET /api/equipment/{equipmentId}/runtime-readings | 返回最近 20 条读数，按记录 ID 倒序，无数据时返回空数组 |
| POST /api/equipment/{equipmentId}/runtime-readings | 提交 `{"hours":123.45}`，返回记录 ID（字符串）、小时数、录入人 ID（字符串）和服务端记录时间（UTC Unix 毫秒） |

累计读数为非负数，最多 12 位整数、2 位小数。拥有设备厂区写入权限的有效企业成员可录入。设备行锁串行化同一设备的写入，与上次读数相等时返回原记录，小于上次读数时返回 409。首版以人工抄表为准，换表、计数器复位和历史补录的业务规则另行确定。已录入读数的设备禁止物理删除，以保留历史记录。

1. 在 Flyway V20 增加读数表，设备复合外键校验企业和厂区，查询纳入现有厂区隔离规则。
2. 先验证接口预期，再实现按设备查询、锁定授权和设备、校验并保存的事务。
3. 设备档案提供读数录入及最近读数列表，展示接口返回的错误。
4. 分别验收空记录、录入 0、有效递增、同值重试、倒退、跨企业与跨厂区、并发及事务回滚。
5. 后续接入小时计划阈值、到期生成工单，再实施故障分类与实际维修和停机时间统计。备件适配约束按独立业务规则验收。

## 验证结果

- 后端使用 JDK 17 编译，隔离 MySQL 8.4.9 全新库应用 Flyway V1–V20。
- 后端套件共 595 项，549 项通过，46 项按环境开关跳过。A7 的 MySQL 用例通过，覆盖无读数、越厂区和越企业读取、同值并发只写一条、倒退拒绝、事务回滚和历史保护。
- MVC 契约覆盖 0 小时、非法精度、空列表和 409 错误原因。前端构建及 99 项契约测试通过。
- 真实登录后的浏览器联调及部署验收待执行。
