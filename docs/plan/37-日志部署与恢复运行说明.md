# 日志、部署与恢复运行说明

适用 Java17、当前 Boot4 单体。配置 profile：ops,redis-session。业务代码、数据库权限与Session/CSRF规则保留。

## 启动前

先构建 `mvnw.cmd -DskipTests package`。核对目标 DB_URL，显式配置 DB_USER、DB_PASSWORD，不把密码放命令行、脚本仓库或报告。配置 REDIS_HOST、REDIS_PORT、REDIS_PASSWORD，两个实例使用同一 REDIS_SESSION_NAMESPACE；确认实际数据库版本及已批准迁移。ops 禁止启动自动 migrate，不会自动执行 V12；迁移必须在备份和目标确认后另行通过 Flyway 执行，禁止手工改历史。JPA validate 不代表完整 Flyway校验，部署前另行 validate。

PowerShell 示例（非秘密变量）：
```powershell
$env:JAVA_HOME='E:/JDK17'
$env:SPRING_PROFILES_ACTIVE='ops,redis-session'
$env:APP_PORT='8080'
$env:MANAGEMENT_PORT='9091'
$env:INVENTORY_EXPORT_ROOT='E:/EquipOps/shared/exports'
$env:OPS_LOG_DIRECTORY='E:/EquipOps/logs/instance-a'
# DB_URL、DB_USER、DB_PASSWORD、Redis参数从受保护环境注入
& "$env:JAVA_HOME/bin/java.exe" -jar ./target/EquipOps-0.0.1-SNAPSHOT.jar
```

第二实例 APP_PORT=8081、MANAGEMENT_PORT=9092、日志目录 instance-b。Session namespace共享；两实例导出根目录使用配置类实际定义的同一绝对路径，共享会话不等于共享文件。不要为启动修改用户现有服务。按启动窗口Ctrl+C正常停止；自动化只停止自己记录PID的进程，不按端口批量杀进程。

## 日志与健康

响应 X-Request-ID 对应日志 requestId，客户端给的编号不可信且会被替换。请求日志不采集URL、参数、正文和请求头；后台导出以taskId定位，未新增跨线程请求编号传播。异步派发日志表示该次派发，不保证非阻塞下载最后一字节送达。

控制台及文件使用同一敏感字段过滤器，省略异常堆栈，SQL诊断文本省略；换行移除，单条消息上限4096。它不是任意个人信息识别器：禁止记录业务对象、任意正文和未知敏感字段，不开启SQL或HTTP DEBUG/TRACE。需要深入故障诊断时应在授权隔离环境采集，不能直接在生产开启全量日志。

日志10MB及每日滚动压缩，14天、归档1GB上限；活动文件不计入归档上限，并非操作系统硬配额。日志/备份目录仅授权运维账号读取，不放前端静态目录。

管理端口只监听127.0.0.1，仅health，健康响应不含组件/详情。同机进程可访问，禁止反向代理公开转发管理端口；不要将它作为独立身份认证。示例 `http://127.0.0.1:9091/actuator/health`。DOWN通常503，应核查MySQL和Redis；健康探针不等于库存业务正确性。业务端口不提供管理端点，其他Actuator端点不开放。

## 恢复与回退

一致性备份须涵盖业务表与Flyway历史；备份期间禁止并发DDL，非InnoDB对象需单独处理。先审查SQL没有跨库写入，仅恢复至新建且原先不存在的独立库。核对表/索引/约束、全表行数与摘要、关键业务关联、Flyway validate；不能以导入无报错判成功。原库不覆盖，恢复库保留待审阅。

备份含敏感数据，只保存在受控目录，不提交Git，报告仅摘要。数据库恢复不涵盖导出共享目录或Redis会话：文件须另有备份和storageKey一致性核对；丢失会话需重新登录。不得将单租户数据直接导入在线共享库。

代码回退与数据回退分开：本单元不增加数据库迁移；停止自有实例后回到经确认的代码/配置快照，不reset用户改动。旧版本若不兼容已有V12需先评审，不能删除历史伪造回退。未作生产恢复时延/RPO承诺。
