# 租户与成员基础模块：表与接口骨架

日期：2026-10-22。范围依据本目录 01～04 文档及用户本次授权：设计并运行表、创建实体、Mapper、Service 接口及 Controller；不实现 ServiceImpl。

## 一、范围和决定

- 新增 tenants、tenant_memberships、tenant_member_roles、sites、warehouses 五张表；复用现有 users、roles，不复用全局 user_roles 作为企业授权。
- 企业编号全局唯一；成员在企业内唯一；厂区／仓库编号在企业内唯一。所有外键使用与原表一致的 BIGINT UNSIGNED。
- 成员角色使用独立自增主键，另以 membership_id + role_id 唯一，方便 MyBatis-Plus 操作。复合外键保证成员角色的 tenant_id 与成员所属企业一致。
- 仓库通过 tenant_id + site_id 复合外键关联同企业厂区，防止跨企业关联。
- 企业、成员、厂区、仓库采用 enabled 布尔状态；不提供物理删除接口，引用使用 RESTRICT。全局账号是否启用与企业成员是否启用分别判断。
- 每个企业最多一个默认厂区、一个默认仓库，由生成列 default_slot 和唯一索引保证。生成列不映射到实体。至少一个默认组织由后续受控初始化事务保证；本迁移不创建虚构企业、用户、成员或默认组织。
- 所有表具备数据库维护的毫秒审计时间；实体对审计列设置 NEVER 写入。新实体仅用 MyBatis-Plus，原有 JPA 实体不改。
- 不修改 V1、不删除旧表、不回填旧业务归属、不修改旧库存；设备／工单尚未具备租户隔离。
- 当前请求 DTO 不接受 tenantId 或 actorUserId 作为授权依据。成员 ID 与全局用户 ID 明确区分。

## 二、迁移策略

V2__create_tenant_foundation.sql 只新增五张表，不含 CREATE DATABASE、DROP、TRUNCATE、旧表 ALTER 或数据写入。

本地 MySQL 已手工创建 V1 的 9 张业务表，但没有 flyway_schema_history；执行前备份，在核对后显式 baseline 到版本 1，再由 Flyway 执行 V2。baseline 是接管已有结构，并不证明手工结构逐字等同历史 V1。已知设备状态默认值由用户手工改过，后续基线审计单独记录；不能对现存数据库重跑 V1。

保留 clean-disabled=true、validate-on-migrate=true；不打开全局 baseline-on-migrate，避免未来误接管未知数据库。新空库依次执行 V1、V2。现有库在本次迁移成功后再次启动只验证，不重复建表。

本项目 Spring Boot 4 需要 Flyway starter 自动配置；将原 flyway-core 直接依赖替换为 spring-boot-starter-flyway，保留 flyway-mysql。业务逻辑不变。

## 三、接口骨架

| 方法与路径 | 对应 Service | 用途 |
| --- | --- | --- |
| GET /api/tenants/mine | TenantService.getMyTenants | 当前登录用户的有效企业 |
| GET /api/tenant-members | TenantMemberService.getMemberPage | 当前企业成员分页，current/size/keyword/enabled |
| POST /api/tenant-members | TenantMemberService.addMember | 将已有用户加入当前企业，userId + roleIds |
| PUT /api/tenant-members/{id}/roles | TenantMemberService.updateMemberRoles | 更新该成员在当前企业中的角色，roleIds |
| PATCH /api/tenant-members/{id}/status | TenantMemberService.updateMemberStatus | 启用／撤销成员关系，enabled |
| GET /api/sites | SiteService.getDefaultSites | S1 当前企业启用的默认厂区 |
| GET /api/warehouses | WarehouseService.getDefaultWarehouses | S1 当前企业启用的默认仓库 |

Controller 使用 ObjectProvider 延迟取得 Service：尚无实现时返回 HTTP 501，不能返回伪造的成功数据。当前返回 501 是预期的未实现状态；不是已经完成成员管理。请求格式不合法仍可由 @Valid 返回 400。

当前没有可信登录／租户上下文；后续实现任何 Service 前，先建立真实身份、有效成员与企业上下文检查，缺少上下文默认拒绝。不要为跑通接口硬编码当前用户／企业，也不要直接接受请求头 tenantId 就授权。该阶段不提供公开企业创建、平台管理、登录签发、切换企业或 S2 多厂区 CRUD。

## 四、字段

| 表 | 业务字段（均另含 id、created_at、updated_at） |
| --- | --- |
| tenants | tenant_code、name、enabled |
| tenant_memberships | tenant_id、user_id、enabled、joined_at |
| tenant_member_roles | tenant_id、membership_id、role_id |
| sites | tenant_id、site_code、name、address、enabled、is_default；内部生成列 default_slot |
| warehouses | tenant_id、site_id、warehouse_code、name、location、enabled、is_default；内部生成列 default_slot |

实体和 DTO/VO 均使用 @Data、@NoArgsConstructor、@AllArgsConstructor，每个字段有中文 JavaDoc。五个 Mapper 只继承 BaseMapper，不声明不安全的无租户自定义 SQL；业务实现仍须显式添加可信当前租户条件。
