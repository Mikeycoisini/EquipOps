## 4. 每一种文件做什么

一次新增设备请求，大致经过：

前端 JSON → Controller 接收 → Service 接口约定 → ServiceImpl 执行业务 → Mapper 操作数据库 → VO/Result 返回。

| 文件类型 | 你可以怎样理解 | 示例 |
| --- | --- | --- |
| Controller | 接请求，调用业务，返回结果 | EquipmentController |
| Service | 声明这个业务提供哪些方法 | EquipmentService |
| ServiceImpl | 真正判断条件、处理状态、组织事务 | EquipmentServiceImpl |
| Mapper | 查询、插入、更新数据库 | EquipmentMapper |
| Entity | 对应数据库表的 Java 对象 | EquipmentEntity |
| DTO | 前端允许提交的数据 | EquipmentUpsertDto |
| VO | 接口允许返回的数据 | EquipmentVO |
| Result | 统一响应的 code、message、data 外壳 | com.common.response.Result |
| Config | 把框架所需组件配置并连接起来 | MybatisPlusConfig、SecurityConfig |
| 迁移 SQL | 记录数据库每次结构变更 | V1、V2 |

Service 接口存在，只能说明方法已经约定。ServiceImpl 方法只有 return null 时，业务仍未实现，即使 Controller 包装出成功响应也不能记为成功。

## 6. 认证文件为什么多

它们共同处理三个问题：当前用户是谁、当前代表哪家企业、在该企业有什么权限。

| 文件 | 作用 |
| --- | --- |
| DatabaseUserDetailsService | 按账号查询用户，供密码认证使用 |
| LoginUser | 框架认证后的用户主体，包含可信 userId |
| AuthServiceImpl | 登录保存、退出、当前身份和企业切换 |
| CurrentAccessServiceImpl | 给业务提供可信 userId、tenantId 和角色检查 |
| SecurityConfig | 装配认证管理器、会话、CSRF 与过滤链 |
| AccessValidationFilter | 在 Controller 前执行通用访问检查 |
| AuthExceptionHandler / ApiSecurityResponse | 分别处理 Controller 内与过滤器中的认证错误 |
| AuthRoleMapper | 读取指定企业成员的角色 |
| AuthSessionAttributes | 集中保存会话属性名称 |
| TenantAccess | 一次企业准入检查得到的组合结果 |

用户账号是全局身份；企业成员关系是这个账号是否属于某家公司；成员角色是这个账号在这家公司能做什么。用户 enabled、成员 enabled、企业 enabled 分别表示不同状态。

当前认证代码使用 Session Cookie，不再返回 Bearer token。获取 CSRF → 登录 → 重新获取 CSRF → 查询 me → 选择企业 → 带会话调用业务。认证代码尚未证明旧业务 SQL 已具备租户隔离。
