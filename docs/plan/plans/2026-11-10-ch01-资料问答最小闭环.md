# Ch01 资料问答最小闭环 实施计划

> **执行方式：** 逐 Task 执行，每个 Task 走完"失败测试 → 实现 → 通过 → 全量回归 → 提交"，不跳步。

**Goal:** 在 Java 与 Python 两个进程之间跑通"上传 MD 资料 → 切分入库 → 词面检索 → 带引用回答 → 任务可查/可取消"，全程租户隔离，不接模型。

**Architecture:** Java 持有原文与任务真相（MySQL + 受控目录），Python 只做切分与检索；引用原文由 Java 重取；`/api/ai/**` 面向浏览器，`/internal/ai/**` 只认任务凭证。

**Tech Stack:** Java 17、Spring Boot 4.0.6、MyBatis-Plus 3.5.15、Flyway、MySQL 8；Python 3.12、uv、FastAPI、pydantic v2、httpx、pytest。

**Spec:** `docs/plan/specs/2026-11-10-ch01-资料问答最小闭环-design.md`

## Global Constraints

- 技术选型定死；走不通停下问用户，不换方案。
- 本章不接模型、不接向量库、不写业务表、不做前端、不做 SSE。
- 迁移只新增 `V16`，不改 V1—V15；执行前核对目标库与备份。
- 身份只从 `CurrentAccessService` 取；请求体不接受 tenantId/userId。
- 问题原文与答案正文落库（spec 第 5 节已确认），按任务与 `tenant_id` 隔离；运行日志仍不记正文全文。
- 响应统一 `Result{code,message,data,timestamp}`；分页用 IPage（records/total/current/size）。
- ServiceImpl 内先写完整编号执行流程注释，再逐行实现并加中文说明。
- 测试不打真实模型、不连外网；MySQL 测试用隔离库，执行前 `SELECT DATABASE()` 核对。
- 每 Task 完成即提交，message 形如 `feat(ch01): <本 Task 内容>`；只提交本 Task 的 Files。
- 不提交 `.env`、`AI_SHARED_SECRET`、资料文件、运行目录。
- 不做清单见 spec 第 2 节；任何范围变化先改 spec。
