## 从新检出复现

准备完整JDK17、Node22.18+、Python3、Docker及Compose。使用既有隔离检出，不创建worktree。不要对现有生产库运行测试初始化器。

在后端创建受保护的本机变量文件，以下命令只在新文件不存在时创建，值不写到终端：

```bash
mkdir -p artifacts/a1
python3 - <<'PY'
import os,secrets
path='artifacts/a1/local.env'
fd=os.open(path,os.O_WRONLY|os.O_CREAT|os.O_EXCL,0o600)
with os.fdopen(fd,'w') as f:
    for name in ['DB_PASSWORD','A1_MYSQL_ROOT_PASSWORD','A1_TEST_PASSWORD']:
        f.write('export '+name+'='+secrets.token_urlsafe(24)+'\n')
    f.write('export DB_USER=equipops_a1\n')
    f.write('export DB_URL="jdbc:mysql://127.0.0.1:13306/equipops_a1_local?serverTimezone=Asia/Shanghai"\n')
    f.write('export A1_DB_CONFIRM=equipops_a1_local\nexport REDIS_HOST=127.0.0.1\nexport REDIS_PORT=16379\nexport REDIS_PASSWORD=\nexport REDIS_SESSION_NAMESPACE=equipops:a1:local\n')
PY
source artifacts/a1/local.env
export INVENTORY_EXPORT_ROOT="$PWD/artifacts/a1/exports"
docker compose -f compose.a1.yml up -d --wait
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/tests -v
python3 scripts/check_public.py . ../OPS-V2.0-
bash scripts/a1_verify.sh
```

验证脚本强制要求`equipops:a1:`命名空间及无符号链接的绝对`artifacts/a1/exports`目录，拒绝`SPRING_*`覆盖变量；先仅编译工具，再用`--check-target`只读核对实际schema，通过后才运行可能触发Flyway的Spring测试。

初始化器建立两个独立测试企业、默认厂区/仓库、`TENANT_ADMIN`角色及管理员/普通成员账号（验收角色沿用V4）。`a1_admin`只在A有管理员角色，在B为普通成员；`a1_member`只属于A。密码来自`A1_TEST_PASSWORD`，不预设公开演示密码。重复运行只验证既有夹具，不覆盖密码、不修改角色。若数据不符则拒绝，不通过清空库来修复。服务停止可用`docker compose -f compose.a1.yml stop`，不要随意删除volume。

前端：`npm ci --registry=https://registry.npmjs.org --replace-registry-host=always`，随后`npm run test:contracts`及`npm run build`。运行浏览器验收时启动后端8082及前端5174，沿用真实身份。Playwright作为可选验证工具单独安装：`npm install --prefix /tmp/equipops-a1-browser playwright`，设置`A1_PLAYWRIGHT_MODULE=/tmp/equipops-a1-browser/node_modules/playwright`和系统`A1_CHROMIUM_PATH`后运行`node scripts/a1_browser.cjs`；进程继承受保护的测试密码，禁止在命令行填明文。

云环境需要Maven代理和Java CA时使用平台继承的网络/信任配置，通过`MAVEN_SETTINGS`与`MAVEN_OPTS`传入；`A1_MAVEN_REPO`可指定已有缓存。TLS与npm完整性校验保持启用。GitHub runner不套用云环境代理地址。
