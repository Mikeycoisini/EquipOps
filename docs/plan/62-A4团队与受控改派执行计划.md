# A4 团队与受控改派执行计划

依据38号M3-R1/R2、41号ER、42号接口及51号A4。A3最终验证后开始，历史V1—V16不改。

## 冻结契约

- V17新增teams、team_members、team_site_scopes及team_operations（请求幂等/结果快照）；work_orders新增可空team_id及version默认0；work_order_reassignments保存请求号、规范载荷hash、结果快照和交接记录。
- GET /api/teams、GET /api/teams/{id}：管理员当前企业全部，普通成员仅自己参加的启用团队，完整VO为{id,tenantId,teamCode,name,enabled,version,membershipIds,siteIds}，ID字符串。
- POST /api/teams：{requestId,teamCode,name,enabled?}；PUT /api/teams/{id}：{requestId,expectedVersion,name,enabled}；PUT /{id}/members：{requestId,expectedVersion,membershipIds}；PUT /{id}/site-scopes：{requestId,expectedVersion,siteIds}。写入仅管理员，成功200并返回完整TeamVO；数组完整替换，空数组撤清。版本安全非负整数、ID严格正整数/十进制字符串、集合最多500。同号同内容返回原结果，同号异内容409。
- POST /api/work-orders/{id}/reassign：{requestId,expectedVersion,targetAssigneeUserId,targetTeamId,reason}，targetTeamId可空（个人接单），reason去首尾空格后1—1000字符，成功200返回WorkOrderVO（新增teamId和version，相关ID字符串）。仅管理员操作；只PENDING/IN_PROGRESS允许，原状态不变。

## 授权与历史约束

1. 团队资格只能收窄个人权限：目标是启用企业成员及启用账号，个人显式厂区（管理员例外为本企业范围）必须覆盖工单厂区；指定团队时还必须属于启用团队且团队工作厂区覆盖该厂区。个人接单不凭团队成员身份扩大范围。
2. 工单普通读仍遵循A3个人厂区范围，报告人不因团队归属丢失合法厂区内历史。团队资格用于团队接单和受控改派，不自动授予厂区访问。
3. 团队停用、移除成员、缩小厂区时若影响该团队未结束工单，409并要求先交接；不自动挪走责任人或删除历史引用。成员及账号停用/个人范围撤权沿用A3下一请求重新授权。
4. 企业→目标团队/成员→工单等锁序、锁后当前读重验管理员及目标资格；版本条件更新与日志/成功审计/幂等结果同事务。既有派单、开工、提交、验收、驳回均推进工单version，保留原状态条件及验收职责分离。
5. 转派只新增责任交接日志及记录，不改既有用料、退料、历史操作者或完成/验收记录。理由保存在受授权业务历史，不把正文记入统一审计；审计仅ID、版本与固定标记。
6. 旧派单保留PUT契约，但目标也必须具备个人厂区资格；不允许用旧入口绕过新授权。

## 执行与验收

1. schema/幂等与版本契约、团队事务服务及失败审计；测试先行。
2. 改派事务/并发/状态与目标资格、旧流程版本接入、成功同事务审计。
3. 团队管理页面与工单改派弹窗，严格字符串ID；企业切换/晚到响应/409重载保护，状态按钮与后端一致。
4. 真实MySQL：个人/团队交集、企业隔离、版本竞争、重复请求、审计失败回滚、原用料/日志保留。
5. 全量后端/前端、真实Session/CSRF HTTP、真实Chromium、独立整分支审查、文档/配套提交与远程CI。

Ruling: 有未结束工单的团队变更须先显式交接，不默默删资格或自动改派；误判可能使管理员需多一步交接，但避免工单失去合格责任方。
