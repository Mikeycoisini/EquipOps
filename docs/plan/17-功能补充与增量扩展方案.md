## 一、参考资料

- [Atlas CMMS](https://github.com/Grashjs/cmms)：设备、维修工单、计划维护和库存的功能组织；后端同样使用 Java Spring Boot。
- [remonalbear/CMMS](https://github.com/remonalbear/CMMS)：设备资料与安装、日常巡检、计划维护、故障和备件之间的关联。
- [InvenTree 功能文档](https://github.com/inventree/inventree-docs/blob/master/docs/features.md)：零件、库存位置和库存信息的组织方式。
- [Snipe-IT](https://github.com/grokability/snipe-it)：参考资产身份、归属和档案管理；其重点是 IT 资产。

本方案参考功能与设计思路，不直接复制项目代码。若以后需要引入代码或依赖，先分别核对许可证及其使用条件。

## 二、第一阶段：完善现有闭环

以下是已有规划的细化，不新增独立的大模块。实施前先检查已有页面、接口及字段，复用已经可用的功能。

| 内容 | 目标与最小实现 | 注意事项 |
| --- | --- | --- |
| 设备档案关联 | 在设备详情中集中查看设备信息、关联工单与维修履历；有用料信息时可查看关联用料 | 优先复用现有接口；数据始终限定当前企业 |
| 验收退回原因 | 工单时间线展示验收人、退回原因及原维修记录，供负责人继续处理 | 先核对现有 reject 逻辑与日志返回字段；不擅自改变审批规则 |
| 库存流水追溯 | 从工单或备件查看领料、退料与流水，能识别所属仓库和关联工单 | 用料汇总不代替原始流水；关联信息不完整时先核对实际数据 |
| 工作台库存风险 | 仓库库存可用并验证后，接入真实低库存统计 | 接入前以当前接口的实际可用状态为准；未知数量不能当成零 |

验收建议：用真实接口走通“设备报修 → 派单 → 维修 → 领料 → 提交验收 → 他人验收或退回 → 查看设备履历与库存流水”，并覆盖跨企业访问、重复请求和失败回滚等关键情形。完成代码不等于真实 MySQL CRUD 或前端联调通过。

## 三、已纳入第二阶段的功能方向

| 功能 | 想解决的问题 | 候选增量方式 | 依赖与边界 |
| --- | --- | --- | --- |
| 计划维护与巡检 | 为设备安排定期维护，记录执行结果 | 新增维护计划、执行记录、查询接口和页面；与设备、必要时与工单关联 | 先确定时间或运行时长触发、负责人、逾期和重复生成规则；暂不假定自动生成工单 |
| 设备与备件适配关系 | 帮维修人员找到适用备件 | 新增设备/型号与备件的关联数据、维护和查询入口 | 先明确按设备还是按型号；关系应受当前企业限制，历史备件停用后仍能追溯 |
| 设备标签或二维码 | 现场快速进入设备档案和发起报修 | 先生成指向已有设备详情的链接或标签，再按需求接入扫描 | 编码只提供设备标识，不能代替登录、企业归属和权限检查 |
| 维修统计 | 识别重复故障和高维护负担设备 | 新增基于真实工单与日志的只读汇总接口和页面 | 先统一故障分类、维修开始/结束及停机时间口径；数据不足时说明不可统计 |

不默认把采购、财务、移动 App、复杂审批或外部系统对接纳入当前开发；出现真实需求并明确范围后再评估。

## 四、保护第一阶段的增量方案

1. **建立基线**：确认第一阶段约定的检查和联调结果，提交 Git，记录提交号或版本标签；数据库备份与迁移版本也要单独记录。代码提交不等于数据库可回滚。
3. **数据库只做增量变更**：通过新的 Flyway 版本新增表或字段，保留既有已执行迁移和数据。迁移前核对目标库、备份、旧数据兼容和回退方案；不能覆盖真实数据库。
4. **保持已有契约兼容**：核对路径、HTTP 方法、参数、返回字段、枚举与错误语义；前端适配现有后端。新增字段或接口前要确认旧调用方仍能正常工作。
5. **逐项接入与回归**：每次完成一个功能后，检查受影响的设备、工单、权限、库存和前端流程，并明确记录实际执行的测试范围。

例如，设备与备件适配关系可以先新增关系表与独立查询、维护接口；原设备和备件 CRUD 可继续使用。若后来要求“领料只能领取适配备件”，已有领料流程必须接入该校验：届时先说明受影响方法和规则，再按用户决定实施。新增表不会自动改变已有业务行为。

## 五、执行顺序与分工

1. 先核对当前非 TODO 功能、数据迁移与前后端联调状态，完成第一阶段基线验收。
2. 再选一个候选功能确认具体规则、接口和影响范围，先列思路、伪代码和最小参考实现。
4. 已标 TODO 的业务继续暂缓，直到用户明确恢复对应项。
5. 每个功能完成后记录：源码与配置变化、迁移是否执行、验证结果、未验证项和兼容性限制。

本文件不授权自动执行迁移、修改现有业务、提交推送或批量实现所有候选功能。
