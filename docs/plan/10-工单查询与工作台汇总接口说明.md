# 工单详情、用料与工作台汇总

日期：2026-10-27。后端项目：D:/Opus/EquipOps。
本次只增加查询，不修改数据库结构，不执行业务数据写入。

| HTTP 接口 | Controller 方法 | Service 方法 | 主要 Mapper 方法 |
| --- | --- | --- | --- |
| GET /api/work-orders/{id} | WorkerderController.detail | WorkOrderService.getWorkOrderDetail | selectWorkOrderEquipment、selectWorkOrderParts、已有工单与日志查询 |
| GET /api/work-orders/{id}/parts | WorkerderController.parts | WorkOrderService.getWorkOrderParts | selectWorkOrderParts |
| GET /api/workspace/summary | WorkspaceController.summary | WorkspaceService.getSummary | selectWorkspaceSummary |

全部接口继续使用 `Result<T>`。Service 从认证上下文取得当前企业 ID，不接收请求指定的企业范围。
Session 认证与企业选择沿用现有认证模块；只读 GET 不需要请求体。

## 工单详情

返回 `WorkOrderVO`。原有工单字段保留，增加：

- `equipment`：关联设备的 `EquipmentVO`。
- `parts`：当前工单用料 `List<WorkOrderPartVO>`。
- `timeline`：已有字段，在详情中加载完整时间线，按时间及 ID 升序。

先校验工单 ID 和企业归属，再分别查询关联资料。设备查询同时限定工单与设备的企业、厂区；
关联设备不可用时返回 409，未知或其他企业的工单返回 404。
未回填企业归属的旧数据不会被本次接口猜测归属或自动展示。
普通工单列表不逐条加载这些关联信息；其 equipment、parts 为未加载的 null。

## 工单用料

返回 `List<WorkOrderPartVO>`，既有字段包含关联 ID、备件 ID、计划量、已领用量、已退回量及审计时间；
补充 `partCode`、`partName`、`spec`、`unit`，便于页面显示真实备件资料。
查询同时检查父工单与备件属于当前企业，隐藏跨企业或尚未核对归属的备件关联。
停用备件仍可作为历史用料展示；没有可见用料时返回空列表。
该接口查询汇总关联表，不伪造领用记录，也不代替原始库存流水查询。

## 工作台汇总

返回 `WorkspaceSummaryVO`，统计当前企业全部工单，不按前端当前页计算。

| 字段 | 含义 |
| --- | --- |
| tenantId | 服务端验证的当前企业 ID |
| totalOrderCount | 企业工单总数 |
| pendingDispatchCount | PENDING 且无负责人 |
| pendingStartCount | PENDING 且已有负责人 |
| inProgressCount | IN_PROGRESS |
| awaitingAcceptanceCount | AWAITING_ACCEPTANCE |
| completedCount | COMPLETED |
| lowStockCount | 当前为 null，表示暂不能提供该指标 |
| lowStockAvailable | 当前为 false，前端应展示暂不可用 |
| lowStockUnavailableReason | 暂未提供仓库库存统计 |

工单统计使用一条 SQL 的 COUNT 与条件求和，没有工单时各数量为 0。
当前尚无仓库库存余额表，不能使用 spare_parts.stock_quantity 冒充仓库库存，也不能返回假零。
因此本次实现工作台工单统计；S1 的低库存统计指标仍需在仓库库存模型实现后接入与验收。
