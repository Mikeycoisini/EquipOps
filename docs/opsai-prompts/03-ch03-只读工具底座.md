# ch03 只读工具底座：设备与维修履历

我要用 Superpowers 模式让 EquipOps 的 Agent 能查真实业务数据，第三步先搭好工具底座，只接两个只读工具，把"模型说要查什么"和"程序允许查什么"彻底分开。

## 功能需求

1. 工具注册表：工具名 → 参数 schema、所需权限、行数上限、超时、返回字段白名单；未注册的名字一律拒绝。
2. 工具名固定 snake_case，契约按 MCP 工具形态（name/description/inputSchema），便于后续封装成 MCP Server。
3. 任务凭证：签发短期凭证（audience / tenantId / userId / taskId / scope / jti / exp），≤10 分钟，防重放。
4. 内部工具网关：`/internal/ai/tools/{toolName}`，独立过滤器链，只认任务凭证，不走 Session/CSRF。
5. `get_equipment_info`：按设备 ID 查档案，企业 + 厂区双重限制。
6. `get_equipment_history`：按设备 ID 查历史工单，上限 20 条，按时间倒序。
7. 回答四分区：`answer` / `citations` / `businessFacts` / `warnings`。
8. 每次工具调用重新查库复核成员有效、企业 enabled、对象归属，不复用签发凭证时的结论。

## 技术栈

- Java 17、Spring Boot 4.0.6、MyBatis-Plus 3.5.15、Flyway、MySQL 8；新增 `com.ai.tool` 与 `com.ai.security`。
- Python 3.12、FastAPI、pydantic v2、httpx；工具调用走 Java 内部接口。
- 凭证用 HS256 或非对称签名，密钥只走环境变量。
- 定死：工具执行只在 Java 侧，Python 不直连数据库、不执行 SQL。

## 本章不做

- 不提供任何写操作（不建、不改、不删设备/工单/备件/库存）。
- 不接 SOP 检索、适配件、库存、告警（ch04 才做）。
- 不做 LangGraph 编排与预算（ch05 才做）。
- 不在工具里复制业务 SQL，只调用既有 Service。
- 不返回 `storage_key`、令牌、凭据、他人隐私、全表计数、成本价。
- 不放开行数上限与超时。

## 验收标准

1. 未注册的工具名被拒绝（400），且不触达数据库。
2. 企业 A 查企业 B 的设备/工单返回 404；无厂区权限的设备不可见。
3. 错误参数（非法 ID、超长字符串、未知枚举）返回 400。
4. 工具超过 3s 时任务降级并给 warning，不挂起。
5. 同一 jti 二次调用被拒。
6. 设备无履历时返回空 facts，不报错、不编造。
7. `businessFacts` 每条带 `toolName`、关键字段、`asOf`。
8. 全量测试通过。
