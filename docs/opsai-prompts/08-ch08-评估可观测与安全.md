# ch08 评估、可观测、安全与可靠性

我要用 Superpowers 模式给 EquipOps 的 Agent 收口，最后一步不加业务功能，只证明三件事：效果可量化、过程可追溯、AI 挂了业务不挂。

## 功能需求

1. 评测：固定评测集（≥30 条人工审核），覆盖有依据/无依据/错误引用/注入/越权/工具失败/诊断风险；脚本一键跑出 Recall@K、引用有效率、正确拒答率、诊断结构完整率、P50/P95 延迟、单任务成本。
2. 可观测：每任务可查 taskId、节点序列、工具调用、耗时、token、错误码；不记正文全文与凭据。
3. 成本账：按企业/按日汇总调用量与成本，超预算有新任务拒绝。
4. 总开关：`ai.enabled=false` 默认关闭；关闭时 `/api/ai/**` 返回 503 `AI_DISABLED`，其余接口正常。
5. 超时与熔断：连接 2s、读 60s；连续失败短路一段时间，恢复后自动闭合。
6. 限流：每用户/每企业/全局；超限 429，不影响业务接口。
7. 日志脱敏：不打印问题全文、资料正文、令牌、模型原始响应。
8. 进程解耦 + 故障演练：杀掉 Python → 业务接口全绿 → 重启后 AI 恢复。
9. 部署说明：启动/停止顺序、端口、目录、配置项、回滚方式。

## 技术栈

- Java 17、Spring Boot 4.0.6、Actuator（仅本机管理端口）；熔断与限流用现有库实现。
- Python 3.12、FastAPI、uvicorn；健康检查与优雅退出。
- 定死：不引入 MQ、分布式事务、服务网格；不上 Langfuse 等外部观测平台（需要时先问我）。

## 前置（不满足就停）

- ch01—ch07 全部通过。
- 部署目标与端口已确认。

## 本章不做

- 不加新业务功能、不改诊断逻辑、不改工具语义。
- 不在生产配置里做故障注入，注入只用于受控演练。
- 不把管理/健康端口暴露到公网。
- 不为"可用性"放宽权限或跳过校验。
- 不改既有业务接口默认行为与路径语义。
- 不对生成类调用盲目重试。
- 不做无证据的"高可用"声明。

## 验收标准

1. 评测报告包含全部指标实测值、逐例结果与失败样本，硬门槛（跨企业泄露、未授权写入、伪造引用、缺免责声明）逐条为 0。
2. `ai.enabled=false` 时 AI 接口 503，`GET /api/equipment`、`GET /api/work-orders` 等仍 200。
3. 杀掉 Python：业务全绿，AI 任务 `FAILED/AI_UNAVAILABLE` 或 503，不挂起。
4. 超时、熔断、限流三者的实际耗时与状态码有记录。
5. 日志样例证明无凭据、无正文全文。
6. 启动顺序两种都通过：先 Java 后 Python、先 Python 后 Java。
7. 进程收尾记录齐全。

## 工作要求

1. 全程走 Superpowers 流程；技能能自动触发就自动触发，没有就直说。
2. 过程留痕：`dev-notes/m7-ch08.md`，每阶段补一段，记关键原话、关键产出、被纠偏的点、翻车与返工。
3. Actuator、熔断器、日志与限流配置的 API 先用 Context7 MCP 查最新文档；没有 Context7 就用官网文档并记版本。
4. 技术选型定死；走不通停下来问。
5. 纯评估类产出用评测集代替 TDD（评测脚本本身可单测）；可单测部分（开关、超时映射、脱敏函数）仍先红后绿。
6. 边界（违反即停）：只改 `src/main/java/com/ai/config/**`、`/client/**`、`/service/**`、`application*.properties`（只新增项）、`ai-service/**`、`scripts/`、证据目录；不动业务接口默认行为。
7. 完结交付：评测报告、停机演练三段结果、配置项清单、部署与回滚说明、测试结果、`dev-notes/m7-ch08.md` 路径。
