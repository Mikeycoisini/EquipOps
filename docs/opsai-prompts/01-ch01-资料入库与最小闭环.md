# ch01 资料入库与最小闭环（不接模型）

我要用 Superpowers 模式做 EquipOps 的工业运维 Agent，第一步先跑通"传资料、问问题、给引用"这条最薄的链路，先不接模型。

## 功能需求

1. 资料接口：上传 Markdown/TXT、列表、详情、追加版本、删除；文件落受控目录，`storage_key` 不出接口。
2. 切分入库：按标题结构切、超长递归切、重叠裁到句号；片段带章节路径、序号、内容哈希，编号从 1 连续。
3. 检索回答：先做词面检索（本章的检索实现就是它），命中片段拼成回答，只返回引用 chunkId。
4. 任务：提问返回 taskId，可轮询、可取消；状态机 + 数据库租约 + 超时看门狗。
5. 引用可核对：Python 只回 chunkId，引用原文由 Java 按 chunkId 从库里重新取，不采信 Python 回传的引用文本。
6. 企业隔离：所有查询带 `tenant_id`，跨企业一律 404，不区分"不存在"与"无权限"。

## 技术栈

- Java 17、Spring Boot 4.0.6、MyBatis-Plus 3.5.15、Flyway、MySQL 8、Redis Session；端口 8082，库 `equipops_v2`。
- Python 3.12、uv、FastAPI、pydantic v2、pytest、httpx；服务只绑 `127.0.0.1:8090`。
- 前端在独立仓库，本章不碰。
- 定死：本章**不接模型、不接向量库、不引 LangGraph**，词面检索就是本章的检索实现。

## 本章不做

- 不接任何模型、不接向量检索、不引 LangGraph/LangChain、不做 PDF/OCR。
- 不接业务只读工具（设备、工单、库存、告警都不碰）。
- 不写任何业务表，只新建 `ai_*` 五张表。
- 不做多轮对话、不做 SSE、不写前端页面。
- 不改 V1—V15 迁移，不重构既有业务代码。

## 验收标准

1. 上传一篇 md 后 `GET /api/ai/documents` 能看到，响应里没有 `storage_key`。
2. 提问返回 202 与 taskId，轮询到 `SUCCEEDED`，`citations` 里每个 chunkId 都能在 `ai_chunks` 查到且属于本企业。
3. 用企业 B 的 documentId / taskId 请求企业 A 会话，均返回 404。
4. 删除资料后再提问，检索不到该资料内容。
5. `ai.enabled=false` 时 `/api/ai/**` 返回 503 `AI_DISABLED`，同时 `GET /api/equipment` 仍 200。
6. 杀掉 Python 进程后提问，任务变 `FAILED` + `AI_UNAVAILABLE`，接口不挂起。
7. `.\mvnw.cmd test` 与 `uv run pytest` 全绿。

## 工作要求

1. 全程走 Superpowers 流程（brainstorm → spec → plan → 逐任务执行 → code review → finish）；技能能自动触发就自动触发，当前环境没有就直说，不要假装走过。
2. 过程留痕：`dev-notes/m7-ch01.md`，每完成一个阶段就补一段，记关键原话、关键产出（spec/plan 路径、评审结论）、被拒绝或纠偏的点、翻车与返工。不许收尾一次性补记。
3. 涉及 Spring Boot 4、MyBatis-Plus、Flyway、FastAPI、pydantic 的具体 API，先用 Context7 MCP 查最新官方文档；没有 Context7 就用官网文档，并在 dev-notes 记版本与链接。
4. 技术选型定死；走不通停下来问，不自行换方案。
5. 边界（违反即停）：只改 `src/main/java/com/ai/**`、`V16__*.sql`、`src/test/java/com/ai/**`、`ai-service/**`、`scripts/`、`docs/plan/evidence/ch01/`；不在请求体接受身份；Python 不连 MySQL；不提交凭据与资料文件；不为过测试而改断言。
6. 可单测的部分照 TDD（先红后绿）；切分这类纯函数必须真跑出失败再实现。
7. 完结交付：演示命令、测试结果、`dev-notes/m7-ch01.md` 路径。
