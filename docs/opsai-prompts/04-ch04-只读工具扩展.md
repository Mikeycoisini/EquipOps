# ch04 只读工具扩展：SOP、适配备件、库存、告警

我要用 Superpowers 模式把 Agent 从"能查设备"扩到"能回答该查什么规范、换什么件、有没有货、现在有没有告警"，第四步按价值排序接四个工具，机制复用 ch03。

## 功能需求

1. `search_maintenance_sop`：检索维修规范/设备手册，返回带 chunkId 的片段。
2. `search_spare_parts`：按设备 ID 查可用备件，只返回本企业启用备件，标明适配关系来源与 `asOf`。
3. `get_inventory_stock`：按备件 ID（可选仓库）查实时余额，数量按三位小数字符串。
4. `get_active_alarms`：按企业（可选设备）查当前 OPEN/ACKNOWLEDGED 事件，不跨企业、不带处置人隐私。
5. 工具选择约束：只能在"已注册 ∩ 本任务 scope"里选，越界即拒并记 warning。
6. 事实标注：每条 `businessFacts` 带 `toolName`、关键字段、`asOf`。

## 技术栈

- Java 17、Spring Boot 4.0.6、MyBatis-Plus、MySQL 8；新增 `com.ai.tool.impl` 四个工具类并注册。
- Python 3.12、LangChain（SOP 检索走既有向量索引）、pydantic v2。
- 定死：复用 ch03 的注册表、任务凭证与网关，不新增第二套执行机制；工具名保持 snake_case。

## 本章不做

- 不做任何写操作（入库、领料、退料、调拨、处置告警都不碰）。

- 不返回成本价、采购价、供应商联系方式、其他企业库存。
- 不放开行数上限（默认 20 条），不做分页透传。
- 不做编排与诊断（ch05、ch06 才做）。

## 验收标准

1. 四个工具各自的字段白名单与返回样例（脱敏后）可对照。
2. 跨企业备件/仓库/告警请求返回 404 或不可见。
3. 实时性：直接改库后立刻查询返回新值，证明没走缓存或索引。
4. SOP 检索返回的 chunkId 能在本企业资料库反查到。
5. 空数据三种都有记录：无适配关系、库存为 0、无告警。
6. Java 白名单与 Python schema 一致，改一边两边同步。
7. 全量测试通过。
