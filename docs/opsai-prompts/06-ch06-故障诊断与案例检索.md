# ch06 故障诊断与历史案例检索

我要用 Superpowers 模式做 EquipOps 最有价值的一条业务链路，第六步实现故障诊断：Agent 自己按步骤查档案、查履历、查手册、找相似案例，最后给出结构化诊断建议和备件推荐。

## 功能需求

1. S1 诊断链路：获取设备档案 → 查维修履历 → 检索手册/SOP → 找相似历史案例 → 分析可能原因 → 给排查步骤与安全注意事项。
2. 诊断输出固定结构：`possibleFaults`（2–5 个，按可能性排序）、`riskLevel`（确定/待现场确认/无法判断）、`diagnosisSteps`（可执行步骤 + 判据）、`recommendedParts`（来自适配关系 + 库存）、`evidence`（文档引用 + 工单号）、`safetyNotes`、`disclaimer`。
3. **免责声明强制**：`disclaimer` 必须出现在结果与页面，文案为"AI 诊断是辅助建议，不是经仪器验证的故障结论"；缺失即缺陷。
4. S2 历史案例检索：对已完成工单做相似检索，返回相似工单号、当时原因、维修方案、更换备件、处理结果，每条带工单号可反查。
5. 备件推荐：只推荐适配关系里存在且本企业启用的备件，并给出库存状态；无适配则明确说明"无适配记录"，不编造型号。
6. 证据可核对：文档引用由 Java 按 chunkId 重取；工单引用按工单号反查，查不到即丢弃。

## 技术栈

- Python 3.12、LangGraph（多步图）、LangChain（模型与检索集成）、pydantic v2。
- 复用 ch05 的 Runtime、ch03/ch04 的工具与 ch02 的检索。
- 定死：不新增工具机制，不新增数据库；诊断结论只来自已检索到的资料与已查到的事实。

## 前置（不满足就停）

- ch05 已通过。
- 资料里确有该设备类型的手册/SOP 样例；没有样例就没有可验收的诊断质量。

## 本章不做

- 不输出"确定故障"，只输出可能性与待确认项；不做故障概率预测。
- 不做自动派单、不创建工单、不写任何业务表（ch07 才做草稿）。
- 不引入预测性维护、传感器时序建模。
- 不用模型编造手册页码、型号、扭矩值、安全规程原文。
- 不做 Multi-Agent 会诊。

## 验收标准

1. 给定一条振动/温度异常的自然语言描述，能完整走完 S1 链路并返回固定结构。
2. 每次诊断结果都含 `disclaimer` 与 `safetyNotes`。
3. `recommendedParts` 里的备件在适配关系与库存中都能对上；无适配时返回空并说明。
4. S2 相似案例返回的工单号能反查到真实工单，且只限本企业。
5. 资料不足时 `riskLevel` 为"无法判断"，不硬给结论。
6. 诊断链路的工具调用次数与总时长在上限内，超限有记录。
7. 全量测试通过。
