# ch07 工单与维修报告草稿、人工确认

我要用 Superpowers 模式让 Agent 能"帮人写好草稿"，第七步做草稿与确认：AI 只起草，用户确认，Java 重新校验后才落业务表。

## 功能需求

1. `draft_work_order`：把自然语言故障描述整理成规范化报修内容、推荐故障分类、生成检查清单、列可能备件。
2. `draft_repair_report`：把维修人员口述的处理结果（如"更换了电机轴承，重新加注润滑油，运行测试正常"）整理成规范化维修记录草稿。
3. 草稿存储：`tenant_id`、`task_id`、`target_type`、`target_id`、`draft_json`、`content_hash`、`state`（PENDING/CONFIRMED/DISCARDED/EXPIRED）、`created_by`、`confirmed_by/at`、`expires_at`。
4. 确认接口：`POST /api/ai/drafts/{id}/confirm`，带 `requestId`，返回写入后的业务对象 ID。
5. 三重校验：权限（重新查库）、业务状态与版本（`expectedVersion`）、重复提交（`tenant_id + request_id` 唯一）。
6. 事务与审计：写入 + 状态更新 + 审计同事务；审计失败则回滚。
7. 展示要求：页面必须展示**确切的将要写入的字段与值**，不是"AI 建议"这种模糊表述。

## 技术栈

- Java 17、Spring Boot 4.0.6、MyBatis-Plus、Flyway、MySQL 8。
- 新迁移 `V17__*.sql`（版本号先与我确认）；审计沿用 `audit_events`。
- Python 侧新增两个草稿工具，走 ch03 的网关与 scope，`scope` 明确标记 draft 类。
- 定死：写入只走既有业务 Service 接口，不新写绕过授权的 SQL。

## 本章不做

- AI 不得在任务完成时自动 insert/update 工单、维修记录、库存。
- 不做自动确认：没有用户显式动作，草稿只能停在 PENDING。
- 不做批量写入、不循环写多条。
- 不修改业务状态机既有规则（如 COMPLETED 不可再改）来"配合"写入。
- 不让手工填写路径依赖 AI：AI 停机时手工路径必须照常可用。
- 不把模型完整对话、凭据写进审计。
- 不复用签发凭证时的权限结论。

## 验收标准

1. 同 `requestId` 同内容返回原结果，异内容 409。
2. `expectedVersion` 不匹配返回 409，不覆盖。
3. 已完成工单再写返回 409。
4. 企业 A 确认企业 B 的草稿返回 404。
5. 两个连接同时确认同一草稿，仅一方成功。
6. AI 停机时手工填写工单/维修记录主线照常通过。
7. 审计能看出"AI 起草 + 用户确认 + 服务端校验通过"。
8. 全量测试通过。
