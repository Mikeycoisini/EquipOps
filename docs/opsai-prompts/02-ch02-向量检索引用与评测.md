# ch02 向量检索、引用与评测

我要用 Superpowers 模式把 EquipOps 的资料问答从"能跑通"做到"敢信"，第二步换上真检索和真模型，并且先有评测、再谈效果。

## 功能需求

1. 向量检索：切分后生成向量并建索引，可按版本删除重建；检索强制带企业过滤。
2. 模型生成：检索结果作为唯一依据生成回答，经 OpenAI 兼容协议接入。
3. 引用校验：Python 只回 chunkId；Java 反查并重取原文，校验同企业、同任务所选版本；伪造引用一律丢弃。
4. 拒答：检索分不足、无命中、资料已删除，三种情况都返回 `INSUFFICIENT_EVIDENCE`，不生成结论。
5. 注入防护：资料正文里的指令当数据，不得改变工具白名单、授权或输出格式。
6. 第二类知识源：**已完成工单与维修报告**也可入库（S2 历史案例检索的基础），与文档分开标记来源类型。
7. 成本记录：每任务记 tokens、模型名、检索耗时、模型耗时、成本估算，Java 与 Python 各记一份可对账。

## 技术栈

- Python 3.12、uv、FastAPI、pydantic v2、LangChain（文档处理与检索组件按需使用）、pytest。
- 模型直连上游，应用侧统一 OpenAI 协议；`CHAT_*` 与嵌入配置全在 `.env`，换供应商不改代码。
- 向量索引先用本地可删除重建的实现，不新增数据库集群；确需新增服务先问我。
- Java 侧只改调用与引用校验，不改接口契约。
- 定死：模型与嵌入都走 OpenAI 兼容协议，不引厂商 SDK；不引 LangGraph（ch05 才用）。

## 本章不做

- 不改 `ai_*` 表结构（确需加字段先改设计文档并确认迁移版本号）。
- 不改对外接口契约（路径、请求体、响应四分区）。
- 不接业务只读工具（ch03 才做）。
- 不做多步编排、不做诊断结论、不做草稿。
- 不把真实企业资料发给未获许可的出域模型。

## 验收标准

1. 同一批问题上，向量检索命中率高于 ch01 词面检索，差异有记录。
2. 三条"资料不足"问题全部返回 `INSUFFICIENT_EVIDENCE`，回答与引用皆空。
3. 两条"资料内注入"样例，白名单与授权未变，输出格式未变。
4. 评测集 ≥30 条人工审核样例，覆盖有依据/无依据/错误引用/注入/跨企业；报告给出 Recall@K、引用有效率、有依据回答率、正确拒答率、P50/P95 延迟、单任务成本。
5. 历史工单入库后可按单号引用，且引用能反查到真实工单。
6. 硬门槛逐条为 0：跨企业泄露、伪造可验证引用、未授权写入。
7. `uv run pytest` 全绿，Java 侧不回归。

## 工作要求

1. 全程走 Superpowers 流程；技能能自动触发就自动触发，没有就直说。
2. 过程留痕：`dev-notes/m7-ch02.md`，每阶段补一段，记关键原话、关键产出、被纠偏的点、翻车与返工。
3. 涉及 LangChain 检索/切分组件、嵌入模型、向量库的具体 API，先用 Context7 MCP 查最新官方文档；没有 Context7 就用官网文档并记版本与链接。
4. 技术选型定死；走不通停下来问。
5. 纯提示词与阈值类产出用标注样例/评测集代替 TDD；可单测的部分（打分、阈值、引用过滤）仍先红后绿。
6. 边界（违反即停）：不改 V1—V15、不改接口契约、不写业务表、不从请求体取身份、不把模型输出当引用原文、不让模型自评、不删失败样本。
7. 评测阈值开跑前冻结，不许先跑数再倒推；不达标如实报告，连续两轮调优无改善即停。
8. 完结交付：演示命令、评测报告路径、测试结果、`dev-notes/m7-ch02.md` 路径。
